# ADR 0003 竞赛编译与提交命令的脚本交付

日期为 2026-11-10。状态为根据用户澄清更新的实现方向，脚本语言与 Windows 兼容性待接入验证。本决策更新 [ADR 0002](0002-linux-rust-stack.md) 的选手命令部分。

## 背景与来源证据

用户希望使用 WF 镜像中编译、提交命令的便利体验，并进一步明确允许自行实现，重点是脚本形式便于统一下发和修改。项目以独立脚本包交付选手命令，WCCS 负责配置、安装、分发和可用性检查。

2026-11-10 核对到以下资料。

- WF 2024 Technical Notes 明确将 C++ 编译命令写作 `compileg++`，通过脚本调用 GNU G++。这是该年份的命令命名和行为证据。[WF 2024 技术说明](https://docs.icpc.global/wp-content/uploads/2024/08/2024-TechNotes.pdf)
- DOMjudge 官方安装文档提供 `submit/submit`，要求 Python 和 requests，并说明服务器地址、比赛和认证配置。读取的上游源码以 Python 3 shebang 开头，文件头包含 GNU GPL 许可说明。接入时应选择与目标 DOMjudge 对应的固定版本。[DOMjudge 工作站安装文档](https://www.domjudge.org/docs/manual/main/install-workstation.html)、[submit 源码](https://raw.githubusercontent.com/DOMjudge/domjudge/main/submit/submit)
- WF 2026 镜像安装说明以 Ubuntu 为运行环境，Windows 适配需验证脚本解释器、路径、编译器及系统命令依赖。[WF 镜像说明](https://image.icpc.global/icpc2026/ImageBuildInstructions.html)
- `icpctools/icpctools` 的官方项目介绍列出展示、Resolver、CDS 等工具。本次尚未定位用户提到的编译脚本仓库及 `compilecpp` 对应文件，记录为 Q-09，后续按实际源码确定归属。[ICPC Tools 仓库](https://github.com/icpctools/icpctools)

以上资料用于参考命令语义和评估复用成本。M3 固定项目命令契约，选择上游代码时同时记录其发行版本、提交号和摘要。

## 决定

1. `compilecpp` 和 `submit` 以源码可读的脚本包交付。逐个命令按复杂度、Windows 兼容性和维护成本选择自行实现、复用或小幅适配上游。
2. `compilecpp` 采用薄脚本封装编译器调用，初步方向为 PowerShell 或 Python，提供 cmd / PowerShell 均可调用的入口。明确参数、输出文件规则、错误反馈和退出码，需要兼容 `compileg++` 时提供别名映射。
3. `submit` 初步采用 Python 3，可接入 DOMjudge 上游脚本，也可依据目标 API 自行实现。先固定比赛、题目、语言、文件、确认交互、提交编号和错误处理的命令契约。
4. 解释器和依赖随比赛镜像或离线工具包交付，具体版本通过普通用户和实际终端验证。环境选用 Windows PowerShell 时验证机房自带版本的能力。
5. WCCS 管理脚本包版本、内容摘要、安装路径、PATH、编译器配置、DOMjudge 地址及比赛配置。以选手权限执行编译和提交，凭据按选手隔离并遵循实际 API 认证方式。
6. 复用代码保留来源、固定提交、许可文件、版权声明及本地补丁记录。自行实现记录采用的接口文档、命令约定和兼容范围。
7. Rust 服务、会话程序及运维工具继续按其职责开发。竞赛脚本使用独立的打包与验证入口。

## 独立发布与统一配置

工具路径管理的责任按 [ADR 0004](0004-server-managed-tool-paths.md) 执行。服务端维护脚本入口、解释器和编译器的完整文件路径，客户端按收到的配置检查。上文 PATH 配置用于部署后选手调用命令。

脚本代码和比赛配置分别版本化。编译器路径、编译参数、DOMjudge 地址与比赛编号通过配置注入，同一脚本包可用于多场比赛。

服务器生成带脚本版本、配置版本、所需解释器及文件摘要的发布清单。客户端通过认证的分发通道下载到暂存目录，校验并检查依赖后激活。完整脚本包采用独立版本目录，启动入口在一次调用中固定所用版本，保留正在执行任务依赖的文件，失败时可回退到上一已验证版本。

脚本更新独立于 Rust 客户端安装包。解释器或运行依赖发生变化时，单独安排相应环境更新与验证。教学模式按既定模式规则处理，比赛中更新通过明确的管理操作选择目标与激活时机。

管理界面显示各机器的脚本和配置版本、下载、校验、激活及失败状态。客户端仅接受授权脚本包，包目录按部署策略限制修改，选手仍可正常编辑工作目录中的代码。

## Windows 适配与验收

- 原生 Windows 优先做最小依赖验证。复用脚本涉及 POSIX Shell 或其他 Linux 能力时，评估兼容环境和等效脚本实现的维护成本。
- 从 cmd、PowerShell 及选定比赛终端调用，验证中文与空格路径、参数边界、引号、工作目录和退出码，避免把文件名拼接成可执行 Shell 命令。
- 编译器及标准由本场比赛配置。使用实际工具链核对产物、失败后的旧产物处理和判题环境差异。
- Python、requests 及任何可选依赖固定版本并提供离线安装材料。检验缺失解释器、证书、依赖和服务器不可达的反馈。
- 网页 IP 自动登录与 submit 的 API 认证分别测试，普通用户可提交自己账号的解答，成功结果可与 DOMjudge 提交记录核对。
- 超时和响应丢失时说明结果待核对，先查询对应记录，重试行为需要防止重复提交。
- 包更新、系统复原和比赛切换后重新检查命令解析路径、包版本和账号配置；更新中断、校验失败和已有命令仍在运行时验证版本一致性及回退。

[ADR 0014](0014-machine-tools-alignment.md) 接入小型 UTF-8 脚本包的独立打包、来源/许可/摘要、运行依赖版本、固定部署模板和逐机回执。当前使用认证维护命令携带有界内容，保留不可变版本目录并最后原子更新 active.json。它提供 M3 的部署基础；compilecpp/submit 命令契约、启动入口固定版本及真实 DOMjudge 提交验收仍属于 M3。

## 2026-11-17 命令实现选择

compilecpp 和 submit 采用项目自行实现的 PowerShell 脚本，复用客户端已交付的 PowerShell 7.6.9。接口依据固定 DOMjudge 9.0.2 源码与 API v4，未复制上游 submit 代码。脚本没有新增 Python 或 requests 运行依赖。

配置由维护页面统一维护，编译器引用现有工具 ID。客户端生成不可变 contest.json，与源码清单分开计算摘要，按维护配置版本建目录，最后更新 active.json。比赛终端只为当前普通用户进程添加命令搜索路径。脚本代码可通过独立清单更新，旧版本文件保留。

submit 使用 DOMjudge IP 认证，提交前显示账号、比赛、题目、语言及源文件摘要。成功与结果未知的相同内容默认复用回执或阻止重复发送，确认重新提交时显式使用 -Resubmit。DOMjudge 文件名规则在客户端提前检查，所在目录允许中文和空格。编译失败清理旧目标程序，编译成功后原子替换输出。

换机时同时更新 DOMjudge IP 和随机密码，以使既有网页会话失效。选手使用 IP 登录，随机密码由管理操作生成。实际 HTTP 会话验证确认旧会话返回 401。DOMjudge 配置 API 的缺失布尔项会被重置，配置更新必须基于完整快照提交并核对，后续 WCCS 账号联动不修改其全局配置。

实际脚本、数据库和原生部署进度见 [M3～M5 开发记录](../tasks/m3-m5-implementation.md)。普通比赛账户命令入口与配置激活的真实实机验证仍待执行。
