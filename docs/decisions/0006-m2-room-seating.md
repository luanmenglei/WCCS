# ADR 0006 M2 机房座位、来源地址与检查范围

日期为 2026-11-10。状态为本轮实现选择，Windows 开发机、PostgreSQL 和浏览器闭环已验证，现场网络待补。

## 背景

管理员需要独立设置不同尺寸的矩形机房、自定义连续编号和方便的 IP 绑定。已有工具配置使用全局配置与完整目标集合，设备注册凭据独立于 IP。版本 1 数据包含已注册设备及历史任务，需要兼容升级。

## 决定

- PostgreSQL 版本 2 增加 Room / Seat 和设备地址观察字段。稳定座位 ID 对应物理行列位置，显示编号可重排，保留位置的 IP 和关联保持稳定。被移除的位置重新增加时获得新 ID。编号与 IP 唯一约束延迟到事务末尾检查，支持批量交换。
- 每间最多 500 个座位、每边 1～50，最多 100 间。起始号为 0～1000000，默认 1、左上按行。IPv4 按全场可见地址空间唯一，后续若存在 NAT / 重叠地址，需要增加经过验证的网络范围标识。
- 保存必须携带机房基准版本及服务器生成的影响预览摘要。摘要包括变更位置、原关联及新匹配设备，状态变化需要重新预览。编辑、请求去重和审计同事务提交。
- 已认证心跳观察来源地址，当前设备与座位关联由最新持久地址和预期 IP 唯一匹配计算。首次观察可自动匹配，地址变化撤销旧位置匹配并要求管理员核对新地址。客户端报告地址作为辅助证据。
- 同 IP 多设备全部显示冲突，离线设备仍保留占用，避免短时掉线触发自动换机。管理员可以按地址基准版本排除占用或恢复参与匹配。排除不撤销设备凭据，凭据生命周期已由 ADR 0007 单独实施。
- 默认直接使用 TCP 对端，忽略转发头。精确配置 `trusted_proxies` 后，对受信任对端读取唯一的 `X-Forwarded-For`，从右向左跳过可信代理。缺失、重复、非法或超过 16 跳的头得到未知来源。部署代理必须正确覆盖或追加真实对端，并限制直接后端访问。
- 机房工具检查只为唯一在线、已注册且属于当前全局配置目标的设备创建任务。未匹配、离线、冲突及范围外目标跳过，并在预览及持久响应中记录。配置版本和展开目标摘要在提交事务内复查。
- 座位保存及地址核对不改变工具配置或任务。检查入口只更新本次执行设备的期望任务。全局发布继续采用 ADR 0005 的完整目标替换语义。
- 沿用单管理员、Cookie / Origin / CSRF 和独立设备 Bearer 认证。管理写入和地址观察使用现有配置头行锁串行化，结合每个机房 / 地址的乐观版本实现多管理员冲突检测。当前吞吐量仍需 M6 验证。

## 影响与验证

数据库迁移保留版本 1 的设备凭据、工具快照、目标、检查历史和请求去重。协议 1 心跳增加可选 `reported_ips`，旧客户端省略时按空列表处理。当前 Windows 入口报告面向服务地址的路由所选本地地址。

真实浏览器完成两个不同尺寸机房的编辑、粘贴、重编号、尺寸变化及并发冲突。真实 Windows 客户端完成回环匹配、工具检查和重复占用核对。代理来源变化通过真实 HTTP 合成转发头测试，真实 Linux / HTTPS / VLAN / NAT / 镜像环境依赖与检查命令见 [任务记录](../tasks/m2-room-seating.md)。

完整角色及机房授权、WSS、Windows 服务、等待界面 IPC 和容量验证继续按 M2 / M6 推进。

## 设备生命周期切片更新

版本 3 迁移已提供注册审核、启用 / 禁用 / 撤销、凭据轮换及重新授权。旧注册设备迁移为 enabled。禁用保留占用、暂停领取，撤销取消未完成任务并释放占用，历史和全局配置目标保留。全局发布可保留禁用目标，显式重查和座位批量检查要求 enabled。注册窗口、请求去重、恢复与验证边界见 [ADR 0007](0007-device-lifecycle.md)。

## 名单分配切片更新

版本 4 已交付显式比赛、选手名单和有效分配，兼容已有设备/工具/机房数据。分配只关联稳定座位，重编号保留，缩减涉及分配时先调整；禁用、撤销和重新授权保留选手计划，设备详情依据当前 IP 匹配显示。事务、导入与历史语义见 [ADR 0008](0008-participant-seating.md)。

## 操作员与事件切片更新

版本 5 已将配置管理员迁入持久账号，实施三角色、显式机房范围、会话版本和事务内授权复核。全局配置、机房/IP、名单及材料写入要求管理员；操作员在授权范围启停设备和重查。旧历史及回执保留，新增事件记录发生时范围，未知历史仅全场身份可查。原文中的单管理员边界由 [ADR 0009](0009-operator-events.md) 更新。
