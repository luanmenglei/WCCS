# ADR 0007 设备注册审核与凭据生命周期

日期为 2026-11-10。状态为已实施，Windows 开发机、PostgreSQL 和真实浏览器已验证。现场环境边界见任务记录。

## 背景

沿用 Natsume 固定基线的审核、启用、禁用、撤销与恢复流程。已读取其 lifecycle、enrollment handler 和 workstation enrollment 实现。WCCS 使用 PostgreSQL 持久审核及 HTTP 轮询，稳定设备 ID 由管理员逐机分配，IP 用于座位匹配。沿用现有依赖。

## 状态与决定

| 状态 | 认证与心跳 | 任务与结果 | 座位 |
| --- | --- | --- | --- |
| pending | 只接受相同注册申请重试 | 无任务 | 不参与 |
| enabled | 当前凭据认证 | 领取有效任务、提交结果 | 按地址核对规则参与 |
| disabled | 当前凭据可心跳 | 暂停领取，已执行结果仍可回传 | 保留占用 |
| revoked | 旧凭据立即失效 | 未完成任务取消，历史保留 | 释放占用 |
| rejected / expired | 拒绝认证及自动重新申请 | 无任务 | 不参与 |

pending 在收到有效申请后可批准或拒绝，材料 24 小时过期。enabled 与 disabled 可互转，两者均可撤销。revoked、rejected、expired 通过管理员重新授权回到 pending，签发新的逐机材料并递增身份代次，始终人工审核。enabled / disabled 恢复丢失状态时先撤销，再重新授权。占用排除仅影响 IP 匹配。

注册窗口默认关闭，管理员可开启一小时或提前关闭。绝对截止时间持久化，重启后沿用剩余时间。开启时首次有效材料申请自动批准，关闭时持久等待审核，已有 pending 不随开窗自动批准。首次提交的随机凭据摘要锁定申请，稳定关联号由材料与凭据摘要派生。其他候选无法替换申请，拒绝和过期后需管理员重新签发。所有使用过的凭据摘要永久保留归属，禁止跨设备与跨代次复用。

状态变更使用设备版本、持久请求编号、配置头事务锁和审计。设备认证在同一事务锁内复查，避免认证后撤销仍写入。禁用阻止后续任务领取，已发出的只读检查可能完成，其结果保留。恢复启用继续未过期任务，过期任务需重新检查。全局发布允许保留已禁用目标并更新其等待任务，设备重查和座位检查仅接受已启用设备。撤销取消未完成任务并清空期望任务，保留配置目标集合、已完成结果和历史，重新授权后需要显式重查。

当前凭据持续有效至显式撤销或轮换提交。轮换由管理员请求，24 小时内客户端先可靠保存候选凭据，再发送当前凭据与轮换编号。服务端事务提交后，旧凭据失去普通 API 权限，仅允许在本次期限内重放完全相同的切换请求。客户端保存新凭据后再继续心跳。响应丢失及中断通过候选文件恢复。再次轮换、撤销或重新授权使旧切换重试失效，期限结束后旧凭据完全失效。

版本 3 迁移把已有注册设备设为 enabled，保留原始材料及 credential、pending、completed 文件格式。`wccs-agent` 升为 0.2.0，心跳协议仍为 1，新增响应字段为可选兼容字段。新客户端优先读取 credential，兼容 identity 内嵌凭据，仅首次迁入文件。旧客户端可继续执行原有接口，轮换需要升级客户端。凭据文件的完整复制会复制 Bearer 身份，部署必须逐机保护身份目录，硬件不可复制密钥留待平台信任切片。

## 影响

管理响应仅含状态、版本、关联号、时间和历史摘要。材料由浏览器本地生成并下载，服务端保存摘要。历史查询保留取消原因与结果，事件与任务分别按游标每页查询 100 条。Linux、HTTPS、跨 VLAN 和机房镜像验证按具体环境补齐。

## 参照差异与重新评估条件

Natsume 基线采用公钥证明、运行中审核及控制连接租约。WCCS 本轮通过管理员分发的逐机材料、预持久化随机凭据、数据库归属约束及事务内复查实现现有轮询协议。申请关联号可从 Windows 输出和管理详情同时核对，重装后还需核对来源地址。Bearer 目录完整复制仍会复制同一身份，当前保证同一凭据无法绑定另一设备 ID，新增客户端同时声明设备 ID 并由后端核验。现场镜像部署应在克隆后逐机注册，硬件防复制需要独立平台密钥设计和验收。

本轮提供逐设备生命周期操作。已有工具及座位批量入口继续预览实际目标和跳过原因，生命周期批量入口随明确需求另行交付。单管理员权限、HTTP(S) 轮询、普通 Windows 进程及 PostgreSQL 单连接模式沿用 ADR 0005。
