# ADR 0009 M2 操作员身份、机房授权与事件查询

日期为 2026-11-10。状态为已实施，开发机验证及现场依赖见 [任务记录](../tasks/m2-operator-events.md)。

## 背景

Natsume 固定基线为 `9b2dca59cf2cd4358c02bc051e318da44cda85e4`。已核对 operator/management、operator/session、db/management、db/session、HTTP authentication、Events 筛选和分页实现。参照稳定身份、最后管理员保护、登录时凭据修订复核和旧响应隔离。WCCS 沿用自身锁定依赖与 PostgreSQL 事务，增加适合多机房的范围授权。上游声明 AGPL-3.0-or-later。[参考源码](https://github.com/4o3F/Natsume/tree/9b2dca59cf2cd4358c02bc051e318da44cda85e4)

## 身份与迁移

- 版本 5 增加 operators、事件投影、请求操作者及任务/设备事件的范围快照。版本 1～4 按原顺序迁移，未知版本拒绝启动，迁移与初始化同事务完成。
- 稳定操作员 ID 与可显示账号、显示名分开。新增账号名允许 3～64 位 ASCII 字母、数字、点、横线和下划线，首尾空白去除，登录及重名检查忽略 ASCII 大小写，账号名创建后保持稳定。旧配置账号保留原始名称和 Argon2 摘要。
- 首次升级时将配置文件管理员初始化为持久、启用、全场管理员。以后启动只读取持久账号，修改配置文件不能覆盖或重新建立账号。原登录 API 和密码继续有效，旧 audit_events.actor 原样保留，历史 actor_id 为空。
- 显示名、角色、范围、启用状态和密码修改统一递增 version。会话绑定稳定 ID 和版本，每次请求在业务事务内重新读取，失效返回 401。修改后清理本进程的相关会话，其他进程依靠数据库版本复核。服务重启仍需重新登录。
- 新设密码为 12～256 字节，禁止控制字符，空白按原样保留。沿用 Argon2、随机盐、现有随机令牌和两个并发密码计算槽。管理员可创建/重置密码，本切片通过管理员重置流程修改凭据。普通响应和事件无密码及摘要，去重回执仅在受保护存储中保存加盐摘要用于核对重试内容。
- 账号保留且允许禁用，不提供删除。所有权限修改持有配置头事务锁，至少保留一个启用的全场管理员。自身调整遵守相同约束，成功后自身旧会话失效。不同请求并发编辑同一版本只允许一个成功。

## 最小授权矩阵

| 操作 | 管理员 | 操作员 | 只读查看员 |
| --- | --- | --- | --- |
| 当前设备、机房、座位、工具状态、选手查询 | 全场 | 授权范围 | 授权范围 |
| 启用/禁用设备、逐机和座位工具重查 | 全场 | 授权范围 | 拒绝 |
| 注册窗口、设备材料、审核、撤销、重新授权、轮换 | 允许 | 拒绝 | 拒绝 |
| 机房/IP 维护、地址核对 | 允许 | 拒绝 | 拒绝 |
| 比赛、名单导入/修改/自动分配/交换/解除 | 允许 | 拒绝 | 拒绝 |
| 全局工具配置发布 | 允许 | 拒绝 | 拒绝 |
| 操作员管理及其变更事件 | 允许 | 拒绝 | 拒绝 |
| 设备历史、全局事件 | 全场 | 授权范围 | 授权范围 |
| 完整名单历史 | 允许 | 全场授权时允许 | 全场授权时允许 |

管理员固定全场。其他角色可指定全场或显式机房集合，空集合代表无机房数据权限。全场授权包含未匹配设备、未分配名单及未知历史范围，限定机房身份只能读取已核对地址且参与座位匹配的设备，以及授权机房座位上的选手。待核对、已排除、未注册、撤销后未匹配设备由全场身份处理。冲突座位仍显示冲突状态，隐藏无法确定授权归属的设备标识。

工具路径是共享全局配置，可供授权身份查询，目标集合按可见设备过滤。限定机房身份看不到其他机房、比赛中其他位置或未分配的选手、注册窗口信息、设备过去地址和客户端声明地址。设备最新结果及原历史接口也按任务创建时范围过滤。

跨机房任务要求所有目标均已授权，整批拒绝混入的越权目标。机房/IP 影响全场地址唯一性和设备归属，名单修改使用完整比赛快照，工具发布替换全局目标，因此这些写操作要求管理员。页面明确展示此边界，后续若细分这些职责，需同时拆分事务影响、预览内容和历史范围。

## API 盘点与事务规则

| 入口 | 服务端校验 |
| --- | --- |
| POST login | Origin、速率、Argon2，事务内复核启用状态及验证密码时的版本 |
| GET session / state | 有效会话及版本，state 在返回前过滤全部领域及结果 |
| POST logout | Cookie、Origin、CSRF，撤销当前会话 |
| GET / POST operators | 管理员，写入复核基准、机房存在性、最后管理员和去重 |
| GET events / events/{id} | 会话、版本、事件范围，操作员变更事件仅管理员 |
| POST devices / registration-window | 管理员，材料独立且回执脱敏 |
| POST devices/action | 启停要求操作员及设备范围，其余动作要求管理员 |
| GET devices/{id}/history | 当前设备范围，再过滤每条历史和任务的已保存范围 |
| POST configuration | 管理员、完整目标和配置基准 |
| POST recheck | 操作员、逐目标范围、状态和配置基准 |
| POST rooms/preview / rooms/save / seating/review | 管理员、原业务预览/版本/唯一性 |
| POST seating/check-preview / seating/check | 操作员、所有座位范围、当前目标及摘要 |
| POST roster/preview / roster/commit | 管理员、比赛基准、完整预览和原业务约束 |
| GET roster/{id}/history | 全场查询授权 |
| POST device/register / heartbeat / result / rotate | 原独立设备认证与生命周期事务复核 |

业务读取、预览、提交与权限编辑使用同一配置头事务锁，取得锁后检查最新身份版本。通过身份校验后才检查去重回执。回执绑定稳定操作者，其他身份不能凭请求编号复用，历史无 actor_id 回执仅管理员可以重放。当前已失去权限的身份即使曾提交成功也必须重新登录并取得对应授权，才能重试。

同请求不同内容返回 409，同请求相同内容返回原持久结果。密码重试校验回执中的原加盐摘要，兼容并发生成不同盐的相同提交。新增设备接受 request_id，旧调用省略时用设备 ID 派生稳定请求编号，继续核对材料摘要和名称。原材料、设备凭据、座位、选手身份及配置保持原语义。

浏览器沿用 HttpOnly/SameSite Cookie、Origin/CSRF，并发送当前登录的 X-WCCS-Session 绑定，跨标签页切换 Cookie 身份时旧页面得到 401。退出或失效统一撤销异步请求代次、清空草稿、预览、材料、选择及敏感详情，轮询每 3 秒发现外部权限变化。

## 事件证据与保留

- events 投影复用 audit_events、device_events、jobs 和 roster_events。数据库触发器与原业务事实同事务提交，回滚不会留下成功事件。管理请求、逐设备下发、设备结果和名单详细结果分别保留来源，并以请求编号关联。
- 稳定事件 ID 为数据库序列，来源表和来源 ID 唯一。字段包含服务器时间、操作者稳定 ID及当时账号名、类别、操作、目标、设备集合、机房集合、比赛、请求、业务版本、结果和详情。任务结果由设备回报，操作者为空，不将发起人伪装成上报人。取消结果关联取消请求，并在详情保留原下发请求。
- 操作员变更详情保留修改前后权限和是否重置凭据。工具事件保留原配置版本及完整检查结果，名单详情复用原持久差异。请求 payload、密码摘要、注册材料、Cookie 和设备令牌不进入事件 API。
- 管理动作的成功、任务等待/取消、文件检查异常和成功、设备事实记录分别查询。失败的管理请求直接返回状态和原因，事务回滚后不生成成功动作事件。认证失败及被拒请求未纳入持久事件流。
- 历史原始操作者文本保留，稳定 ID 和机房范围缺失时为空。旧任务缺少创建时间及接收时间时以内部 0 排序，页面显示历史时间未知。旧证据不依据当前账号、IP 或座位关系补造历史字段。
- 新事件固定当时范围。限定机房身份只能读取非空且全部包含于授权集合的事件。全场/未知事件要求全场授权。先执行授权谓词，再筛选和分页，详情对越权及不存在统一返回 404，没有未过滤总数或聚合选项。
- 时间含上下界，操作者、类型、类别、设备、机房、比赛、请求和结果使用精确过滤。按时间及 ID 倒序，游标携带首屏最大已提交可见 ID、末条时间/ID和筛选摘要。翻页排除后续新增及回填的旧时间事件，筛选变化须重新查询。每页默认 50，最多 100。
- 原设备、配置、请求、名单及任务记录继续保留。事件与原记录永久保存，本切片不提供删除/归档或保留期清理。容量与索引效果在 M6 按长期运行量验证。

## 后续条件

本轮保持 PostgreSQL 单连接、HTTP(S) 轮询和 Windows 普通进程入口。Linux 原生、HTTPS、VLAN/NAT/ACL 和机房复原镜像需要对应环境，Windows 服务、WSS、等待界面 IPC 与批量控制进入下一切片。打印和拍照继续排除，DOMjudge 与选手脚本按 M3 实施。

## 等待控制切片更新

2026-11-11 版本 6 已接入 Windows 服务宿主、WSS 和受保护 IPC 的等待控制。HTTP 保留工具任务独占所有权，等待命令绑定固定选手/座位快照、设备代次和生命周期版本、操作者权限版本、宿主与会话。管理员及授权操作员可批量进入/结束，只读身份查询。服务端和宿主重启回到教学待机，旧授权失效。全局事件继续依据发生时范围，完整语义及实测边界见 [ADR 0010](0010-waiting-control.md)。
