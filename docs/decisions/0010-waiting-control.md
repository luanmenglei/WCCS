## 控制与恢复语义

- 管理员或授权操作员显式提交 `enter` 才启用所选目标的等待控制。服务器上线、设备注册、创建比赛和客户端启动均保持教学待机。本轮只有立即操作，比赛时间安排进入 M3。
- `leave` 是独立显式命令，撤销旧进入目标并等待实际窗口退出。无可用会话、进程或 IPC 故障均保留失败证据。离线且已有宿主身份的目标可排队结束，页面显示离线和实际状态未知，完成以新回执为准。
- “重新核对”读取当前持久命令和最新观察，不续期、不重新执行。异常目标重试先选取异常座位，再预览并创建新命令。提交响应丢失使用原请求编号和完整原内容重试。
- 命令包含协议版本、稳定命令编号、请求编号、全局递增序号、设备 ID、注册身份代次、设备生命周期版本、宿主实例、用户会话键、比赛与名单版本、机房版本、稳定选手/座位 ID、姓名/学校/显示座位快照和绝对截止时间。
- 预览摘要覆盖所选目标、当前比赛版本、身份、机房、设备生命周期/地址版本、控制在线状态、宿主、会话及当前命令头。提交同事务重新计算，变化返回 409。其他批次先更新命令头时需重新预览。
- 每条命令在下发及回执写入前复核操作者启用/版本/角色/范围，设备启用/身份代次/生命周期版本，精确座位 IP 匹配、占用唯一性和地址核对状态。进入还复核比赛/名单、机房版本、选手分配和原用户会话。禁用后恢复也会因为版本变化取消旧命令。
- 命令期限为 30～3600 秒，页面默认 900 秒。用户会话只持有至多 15 秒的短租约，通过 IPC 刷新。客户端另保存首次领取计算的单调时钟期限，后续时钟回拨不能延长已领取命令。
- 断线后宿主结束其精确子进程，窗口自身也会因 IPC 中断或租约到期退出。已执行命令保持消费记录，重连后先报告持久回执与当前观察，同一命令不会重新创建窗口。重新进入需要新预览和新命令。
- 宿主重启产生新实例号，系统重启同样如此。服务端取消绑定旧实例的命令。服务端启动事务取消此前有效命令、保留原完成回执和全部事件，并将连接标为断开。重启后旧管理会话失效，需重新登录显式启用。
- 当前部署仍是单服务端进程和单 PostgreSQL 连接。服务端进程重启会取消等待授权，数据库连接中断仍需重启服务端恢复。多服务端高可用及自动续期另行设计。

## 状态与证据

| 字段 | 语义 |
| --- | --- |
| command.action | 管理端期望进入等待或普通桌面 |
| pending | 数据库已接收，尚未有设备接收证据 |
| accepted | 宿主已持久接收命令 |
| executing | 已进入实际执行阶段 |
| succeeded | 进入有同命令、同会话和至少一屏实际显示证据，结束有窗口清除后的桌面证据 |
| failed | 执行失败，保留有界原因码，允许重新预览 |
| cancelled / expired | 授权失效、被新命令取代或到期，保留原 report |
| actual | 最新会话观察，含 waiting、desktop、no_session、failed、unknown |
| online | 当前服务端代次下的 WSS 连接且观察未超过 15 秒 |

历史 succeeded 不能替代当前 actual。本地退出或窗口异常后历史完成回执保留，当前状态显示失败。离线时 API 返回 actual=null，浏览器显示未知。部分屏幕创建失败不会发送成功观察，UI 线程错误退出后宿主报告失败。输入触碰只在原生窗口聚合计数，协议和持久记录不保存按键内容。

## WSS 边界

`GET /api/device/control` 使用 Bearer 与 `X-WCCS-Device-ID`，子协议 `wccs-control-v1`。设备通道拒绝浏览器 Origin。远程地址要求 HTTPS/WSS，纯回环允许 HTTP/WS。TLS 终止在部署反向代理，需转发 Upgrade/Connection 并允许持续连接。可信源 IP 观察继续由原 HTTP 心跳处理，IP 只参与座位匹配。

首条消息携带版本、宿主实例、当前会话、`waiting-v1` 能力、实际状态及可恢复回执。首条有效消息原子取得连接编号，新连接替代旧连接。每次后续读写复核编号、服务器代次和当前凭据。轮换、禁用、撤销或代次变化后的旧连接失去写入能力。

消息/帧最大 64 KiB，写缓冲最大 128 KiB。一问一答，每秒一次，服务端至少间隔 200ms，无待发送命令无界队列。连接超时 5 秒、发送超时 3 秒、客户端等回复 5 秒、服务端等消息 10 秒。退避加倍至 30 秒并加 0～2 秒抖动，稳定连接一分钟后重置。重复相同回执返回确认，完成后不同内容、乱序、旧命令和错误代次拒绝。标准错误与日志采用固定原因码。

## Windows 服务与 IPC

SCM 安装脚本要求明确服务名、安装目录及身份文件，核对同名服务的完整启动配置。服务使用 LocalSystem，安装目录及其父目录必须防止普通用户替换可执行文件，数据目录只允许 SYSTEM 和管理员。服务与会话 exe 位于同一受保护 bin 目录，当前服务可查询、显式启动/停止及卸载。卸载保留身份与日志，异常退出按 10 秒、30 秒恢复，重启后教学待机。

生产会话选择为唯一活动的物理控制台用户。WTS 会话状态与锁定状态必须明确可用，RDP 作为前台、多个活动会话、锁定、无人登录或状态查询失败均拒绝进入。会话键包括会话号与登录 AuthenticationId，注销再登录不会继承旧授权。当前控制窗口收到系统会话通知即退出，后续需重新预览。现场 RDP、锁定、注销及多用户条件待补验。

服务通过 WTSQueryUserToken 和 CreateProcessAsUserW 以目标用户令牌在 `winsta0\default` 启动窗口。Session 0 保持服务职责。生产子进程由 SYSTEM 拥有，进程和线程 DACL 只给 SYSTEM/管理员完全访问，Owner Rights 仅保留读取控制权限，阻止同用户普通进程注入或复制 IPC 句柄。子进程创建时还启用扩展点禁用与 Microsoft 签名 DLL 限制，覆盖启动阶段的桌面 hook / DLL 注入路径。实际测试窗口可正常启动，进程策略只读查询确认两项为 ON。启动环境块、线程/进程/令牌句柄与 WTS 缓冲均由集中 FFI 封装释放。[微软进程创建说明](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessasuserw)

每次子进程使用随机命名管道，首实例独占、拒绝远程访问，DACL 仅授予 SYSTEM、管理员和所选用户 SID。服务通过内核查询的客户端 PID 对照持续持有的精确子进程句柄。会话端核对管道服务 PID、服务进程令牌和同目录 agent 可执行文件路径，采用 Identification SQOS 防止服务端借用客户端令牌。消息模式、64 KiB 边界、协议版本、命令完整内容、会话键和租约同时校验。旧实例、未授权对端和损坏消息关闭连接。子进程正常退出后清理窗口，服务对异常子进程通过精确句柄停止并确认退出。

前台测试模式按同一用户、真实 PID 与 exe 路径验证 IPC，允许当前用户操作测试文件。生产跨用户 DACL、SYSTEM 子进程保护和 Session 0 启动需要提升权限环境验收。开发测试窗口保留按钮、Esc、Alt+F4 退出，使用普通缩小窗口。原 M1 独立原型入口保持可用。

## 授权与事件

管理员全场，操作员在授权机房可预览、提交进入/结束、重试，只读查看员查询授权范围。所有直接 API 均检查会话、角色与范围，写入同时校验 Origin/CSRF。预览也要求操作权限。查询和重放继续复核当前账号权限，命令历史按创建时范围过滤。混入越权座位整批拒绝。

新增 `control_devices` 与 `waiting_commands` 的版本 6 迁移保留版本 1～5 所有数据。命令、请求回执、审计和事件同事务提交。相同编号不同内容拒绝，相同内容返回原持久回执，原操作者绑定沿用 ADR 0009。

事件记录管理提交、逐机接收/执行/完成/失败、连接变化、实际状态变化、取消与过期。命令事件含固定比赛/机房/选手快照、请求与命令编号、版本和代次。批量管理事件的范围包含全部预览目标及跳过项，逐设备事件使用该设备的历史范围。计数、分页和详情复用 ADR 0009 的先授权后过滤规则，旧工具/生命周期/名单/座位历史继续可查。

任务列表在授权过滤后按设备与比赛选取最新命令，最多返回 500 项，支持 contest_id 筛选。单设备的历史重试不会挤占其他设备状态。长期历史通过事件游标入口查询。当前实际界面属于其他命令时单独标明，避免将旧身份快照视作当前显示。服务端无输入内容采集，普通响应无注册材料和设备凭据。容量、真实 HTTPS/WSS、跨 VLAN、机房镜像与多屏继续按环境补验。

进程启动缓解策略使用 STARTUPINFOEX 的 PROC_THREAD_ATTRIBUTE_MITIGATION_POLICY，存储和策略参数在创建期间保持有效，并经 RAII 删除属性列表。该限制只作用于 WCCS 会话子进程，现场辅助软件兼容性需随机房镜像验收。[微软进程属性与扩展点文档](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)

## Administrator 现场条件修正

2026-11-11 用户确认选手使用 Administrator，密码统一且公开。既有数据目录及进程 DACL 对 SYSTEM 和管理员授予访问权限，因此本地管理员可修改配置、干预服务并接触设备凭据。前述普通权限 IPC 验证继续作为对应测试条件下的证据，生产防干预能力需按新确认的账户条件重新评估。

下一优先切片为统一登录与 Administrator 场景适配，覆盖登录入口、实际会话完成证据、等待控制衔接及干预后的观测和恢复。Windows 登录三类机制尚未实现，技术选型待验证。
