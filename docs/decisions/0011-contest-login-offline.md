# ADR 0011 比赛账户、即时登录与离线恢复方案

状态为设计草案，2026-11-11。用户要求设计新建比赛账户后的统一登录，并处理非比赛及服务器不可达场景；开机自动登录移出本轮目标。账户和策略变更尚未实现或执行。

## 目标与拟定方案

教学沿用现有 Administrator 及既有教学登录习惯。比赛拟使用每机独立的普通本地账户，账户按 WCCS 所有权标记和 SID 管理，避免接管同名既有账户。管理员在网页选择比赛与设备，预览当前会话、账户、工具可用性和恢复条件，再显式准备并登录比赛账户。

优先验证 NetUserAdd 创建账户与 Credential Provider V2 接入登录界面的路线。服务持有设备认证与操作状态，登录组件通过受保护本地 IPC 获取一次性、短期、绑定本次启动与操作编号的登录请求。请求消费后清除凭据，服务或系统重启后重新确认登录。真实完成须看到目标 SID 的活动控制台会话、桌面和会话程序回执。开机保持正常 Windows 登录流程。锁屏解锁独立验证，已有教学会话需先保存工作并由运维明确结束。

Windows 提供账户创建接口以及默认凭据提交和凭据变化通知接口，具体远程触发、会话切换、失败恢复和 Windows 10 镜像兼容性仍需原型实测。[账户创建](https://learn.microsoft.com/en-us/windows/win32/api/lmaccess/nf-lmaccess-netuseradd) [登录请求接口](https://learn.microsoft.com/en-us/windows/win32/api/credentialprovider/nf-credentialprovider-icredentialprovider-getcredentialcount)

## 教学与比赛状态

| 本地已确认状态 | 服务器不可达时的拟定行为 |
| --- | --- |
| 教学 | 保持原教学账户、桌面及登录方式，服务后台退避重连；联网恢复后仍需显式启用比赛 |
| 准备中 | 每步持久记录；尚未确认比赛启用而连接丢失时停止推进，按已完成步骤撤回临时账户策略，保留文件；撤回失败显示待人工恢复 |
| 比赛已启用 | 保留现有比赛用户会话、文件和已应用账户策略；页面显示离线，恢复连接后先核对本机状态，再处理新操作 |
| 恢复教学中 | 已接收的恢复任务依靠本地记录继续执行并可重试；完成后回到教学，联网后补传结果 |
| 状态损坏或与系统不符 | 报告恢复异常，提供运维离线恢复入口，明确实际账户状态，等待核对 |

比赛启用需要先持久保存本机接受的明确授权，再应用限制。服务端回执丢失时按同一操作编号查询；客户端已确认启用的状态与服务端未知分别显示。服务器上线、失联、命令重放或时间变化均不会自行创建新比赛会话。

服务端单独重启后，客户端已生效账户策略和会话需重新核对，避免将其当作教学状态。宿主重启只恢复步骤核对和本地恢复能力。系统重启停留正常登录流程，旧登录请求失效。复原软件可能同时恢复账户和系统盘记录，需在真实镜像验证一致性；单独保存在 D 盘的旧标记不得作为重新启用比赛的依据。

## 公开 Administrator 密码的处理

比赛普通账户方案需要同时处理公开密码带来的提权路径。拟在比赛启用时临时禁用公开的 Administrator 账户，检查其他已知管理员入口，并确认旧管理员会话及可干预比赛的进程已结束。账户禁用不能撤销已存在的管理员令牌。隐藏登录图标不足以完成这一步。

先配置并验证仅运维掌握凭据的独立恢复管理员和原生 Windows 密码登录入口，再变更公开账户状态。恢复材料每机独立，工作人员能在服务器关闭时取得，凭据进入受保护存储并避免日志与普通 API 回传。比赛结束恢复原账户启用状态及本次修改过的策略，停止比赛登录授权；比赛文件留存直到独立归档清理流程执行。该账户策略属于待批准和实测的设计选项。

这能缩小普通比赛账户可干预范围。既有管理员会话、已被篡改的镜像和物理离线攻击需要独立现场控制，完成标志只能建立在实际检查结果上。[微软本地账户权限](https://learn.microsoft.com/en-us/windows/security/identity-protection/access-control/local-accounts)

## 无服务器时恢复教学

工作人员使用独立恢复管理员进入本机，通过本地恢复工具核对比赛与设备，显式结束比赛并恢复教学。工具读取本地操作日志，逐项核对、恢复并记录结果，可重复运行。恢复操作可能需要退出比赛账户，需先保存选手文件并显示影响。选手使用的公开教学密码不能批准该恢复操作。

默认方案采用管理员显式结束或现场离线恢复，比赛模式的结束时刻待比赛安排功能单独设计。关闭服务器本身不会终止正在进行的比赛。若工作人员忘记结束比赛，机器会保留比赛状态，需要本地恢复；这一运维取舍在确认方案时明确展示。

## 与现有 M2 的关系

当前 M2 等待窗口使用最长 15 秒租约，断线会退出，服务端重启会取消旧等待命令。该行为仍是当前实现。下一切片需要将账户/教学模式与等待窗口租约分开建模，退出等待窗口仅回到比赛账户桌面，恢复公开管理员入口需独立恢复教学操作。比赛等待期间断线是否继续覆盖屏幕留作显式策略验证，现有测试结果保持原范围。

## 实施顺序与验收

1. 在独立可恢复 Windows 10 环境验证创建普通账户、Credential Provider 即时登录及错误凭据反馈，保留原生恢复登录入口。
2. 完成离线恢复管理员与本地恢复工具，验证服务端关闭、步骤中断、重复恢复、记录损坏和系统复原。
3. 验证公开管理员账户禁用、既有会话结束、提权路径和教学恢复；记录所需运维确认。
4. 接入管理页面、预览、授权、持久步骤、逐机结果、事件与等待界面，覆盖部分失败、断线、服务重启和响应丢失。

本轮只落实方案及范围调整。系统账户、登录组件、密码、当前工作会话和开机配置均未变更。
