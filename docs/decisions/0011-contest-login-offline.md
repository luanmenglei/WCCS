# ADR 0011 比赛账户、即时登录与离线恢复方案

状态为受限测试实现，2026-11-11。管理闭环、文件故障模拟与 Windows 原生测试适配器已实现。原生适配器限于明确配置的独立可恢复测试机，部署验收以实际证据为准，见 [任务记录](../tasks/m2-contest-login.md)。

## 目标与拟定方案

教学沿用现有 Administrator 及既有教学登录习惯。比赛拟使用每机独立的普通本地账户，账户按 WCCS 所有权标记和 SID 管理，避免接管同名既有账户。管理员在网页选择比赛与设备，预览当前会话、账户、工具可用性和恢复条件，再显式准备并登录比赛账户。

优先验证 NetUserAdd 创建账户与 Credential Provider V2 接入登录界面的路线。服务持有设备认证与操作状态，登录组件通过受保护本地 IPC 获取一次性、短期、绑定本次启动与操作编号的登录请求。请求消费后清除凭据，服务或系统重启后重新确认登录。真实完成须看到目标 SID 的活动控制台会话、桌面和会话程序回执。开机保持正常 Windows 登录流程。锁屏解锁独立验证，已有教学会话需先保存工作并由运维明确结束。

Windows 提供账户创建接口以及默认凭据提交和凭据变化通知接口。独立 Windows 10 虚拟机已验证普通账户创建、远程显式触发登录和默认桌面回执，教学会话退出及现场镜像兼容性继续按任务矩阵补验。[账户创建](https://learn.microsoft.com/en-us/windows/win32/api/lmaccess/nf-lmaccess-netuseradd) [登录请求接口](https://learn.microsoft.com/en-us/windows/win32/api/credentialprovider/nf-credentialprovider-icredentialprovider-getcredentialcount)

## 在线前提与断线恢复

用户明确网络异常时退出控制。此决定替换之前提出的离线保持比赛、等待人工结束及依赖本地截止时间判断的方案。只有已认证控制连接可用且管理端明确启用时，客户端才应用比赛控制。

| 当前情况 | 处理目标 |
| --- | --- |
| 教学且无服务器 | 保持原教学使用方式，后台重连 |
| 准备中断线 | 停止新步骤，撤回已应用的临时限制，保留文件 |
| 比赛中断线 | 关闭等待窗口，失效未消费登录请求，撤销本轮账户及其他可恢复限制 |
| 恢复操作进行中 | 依靠本地步骤日志继续重试恢复，结果待联网回传 |
| 重新连接 | 上报实际恢复结果，隔离旧命令，等待新的预览和启用操作 |
| 恢复失败 | 明确记录失败与仍生效项，提供现场恢复，避免误报已恢复 |

连接明确关闭时立即处理。网络静默丢包通过短心跳超时发现，采用单调计时；当前 M2 窗口租约上限为 15 秒，后续账户恢复延迟须独立实测。系统日期不参与是否允许离线继续控制的判断。宿主或系统重启后旧在线授权失效，优先核对并撤回残留限制。复原软件造成日志与账户状态不一致时需逐项核对，D 盘旧记录只能供恢复诊断。

本地持久状态用于记录本轮做过哪些修改及如何撤回。断线后保持当前比赛账户桌面、编译器和未保存文件，恢复教学账户的可用性；切换登录账户由用户或工作人员正常操作。新登录停止推进时应核对已完成的 Windows 登录结果，避免强制注销已经创建的用户会话。

这一规则允许主动断网触发限制撤销，客户端控制能力明确依赖在线条件。服务器端权限检查保持有效，服务端对失联设备显示状态未知，恢复成功需要设备实际回执。此取舍按用户要求采用。

## 公开 Administrator 密码的处理

比赛普通账户方案需要同时处理公开密码带来的提权路径。拟在比赛启用时临时禁用公开的 Administrator 账户，检查其他已知管理员入口，并确认旧管理员会话及可干预比赛的进程已结束。账户禁用不能撤销已存在的管理员令牌。隐藏登录图标不足以完成这一步。

先配置并验证仅运维掌握凭据的独立恢复管理员和原生 Windows 密码登录入口，再变更公开账户状态。恢复材料每机独立，工作人员能在服务器关闭时取得，凭据进入受保护存储并避免日志与普通 API 回传。比赛结束或确认断线后恢复原账户启用状态及本次修改过的策略，停止比赛登录授权；比赛文件留存直到独立归档清理流程执行。当前测试适配器采用此方案，生产采用条件为独立恢复管理员验证通过、旧教学会话已明确退出、所有目标机失败路径验证完成。

这能缩小普通比赛账户可干预范围。既有管理员会话、已被篡改的镜像和物理离线攻击需要独立现场控制，完成标志只能建立在实际检查结果上。[微软本地账户权限](https://learn.microsoft.com/en-us/windows/security/identity-protection/access-control/local-accounts)

## 无服务器时恢复教学

正常断线恢复由仍在运行的本机服务自动执行，读取本地步骤日志逐项撤回本轮修改，恢复公开教学账户的原启用状态。自动恢复失败、服务损坏或日志异常时，工作人员使用独立恢复管理员和本地恢复工具处理。账户保护方案须先证明断线及进程重启后的撤回路径可用，再接入批量启用。

## 与现有 M2 的关系

当前 M2 等待窗口使用最长 15 秒租约，断线会退出，服务端重启会取消旧等待命令，与此次在线控制方向一致。版本 7 将准备登录、恢复教学、账户实际状态和连接代次接入同一命令与事件链。历史窗口验证不能作为账户恢复完成的证据。

## 完整流程核验补充

本节为设计约束。Windows 10 单机登录、断线账户撤回、SCM 启动恢复与独立恢复工具已有真实证据，未完成的现场和会话条件保留在任务记录中。

- 预览绑定设备身份代次、比赛和座位快照、当前控制台会话、在线连接代次及账户计划；提交与每个特权步骤均复核授权。账号权限撤销、设备禁用和身份变化同样触发撤回。
- 教学 Administrator 的注销需要明确目标及确认，先保存工作；已结束的教学会话无法靠回滚重新恢复其程序。断线回退目标为恢复账户可用性和本轮设置，已经登录的比赛会话保留。
- 准备顺序为核对恢复入口、创建或核对比赛账户及工具、保存本轮修改前状态、明确结束旧管理员会话、应用临时账户策略、即时登录、核对真实桌面。任一步失败停止后续步骤并撤回已应用限制。账户恢复只修改本轮拥有的字段，外部并发变更出现冲突时报告并交由运维核对。
- 登录组件仅接收服务已认证的一次性本地请求，服务持有网络连接。保留 Windows 原生密码登录入口。Credential Provider 提交凭据后的成功仍需核对目标用户桌面；凭据提交后恰逢断线时记录实际结果并保留已经建立的会话。
- 断线撤回与新启用串行处理，撤回未完成的设备暂不接受新启用。同请求重试返回原结果，新连接和新管理员确认产生新授权；重连先核对实际状态，旧登录和控制请求不可重新消费。
- 断线后管理员账户恢复可用，用户可能取得管理员权限。因此再次启用前重新检查会话、提权入口、程序与配置状态。保持在线状态本身不能证明客户端未被篡改。
- 普通比赛账户密码按设备生成并受保护存储，服务器命令指定操作与目标。恢复管理员使用独立运维凭据，提供服务器关闭时可用的取得方式。比赛账户及文件在断线时保留，清理和账号删除由后续显式任务处理；不同场次复用时核对旧会话和文件访问隔离。
- 错误系统日期可能使 HTTPS/WSS 证书校验失败。此时按离线退出控制并报告连接错误，继续执行证书验证。心跳持续时间使用单调计时；休眠恢复后先失效旧在线授权再核对连接，不能用旧心跳继续控制。
- 若服务挂死、被终止或系统故障，持久账户设置可能暂时残留。SCM 恢复后先撤回残留，独立本机恢复入口处理自动恢复失败。只有现场验证这些路径后才能宣称达到断线恢复目标，窗口的 15 秒租约不代表账户恢复也在 15 秒内完成。

账户禁用采用 Windows 支持的账户标志接口。登录组件仅负责提交凭据，权限由 Windows 账户机制执行，原生恢复登录入口持续保留。[账户标志接口](https://learn.microsoft.com/en-us/windows/win32/api/lmaccess/nf-lmaccess-netusersetinfo) [登录组件与恢复入口](https://learn.microsoft.com/en-us/windows/win32/secauthn/credential-providers-in-windows)

## 实施顺序与验收

1. 在独立可恢复 Windows 10 环境验证创建普通账户、Credential Provider 即时登录及错误凭据反馈，保留原生恢复登录入口。
2. 完成离线恢复管理员与本地恢复工具，验证自动断线恢复、服务端关闭、步骤中断、重复恢复、记录损坏和系统复原。
3. 验证公开管理员账户禁用、既有会话结束、提权路径和教学恢复；记录所需运维确认。
4. 接入管理页面、预览、授权、持久步骤、逐机结果、事件与等待界面，覆盖部分失败、断线、服务重启和响应丢失。

本轮系统操作的用户授权仅覆盖 `WCCS-Login-Test` 虚拟机。开发机系统配置的操作边界继续按任务要求执行。

## 实现与恢复边界

`wccs-agent` 的 `login_native` 串行执行原生步骤，`login_windows` 集中封装账户、DPAPI、令牌与 WTS 句柄。预写日志包含机器 MachineGuid、设备、随机所有权标记、目标与教学 SID、操作和序列、原 flags 与步骤。创建账户前记录创建意图并保存每设备随机密码。重试只核对已有所有权、SID 和对应凭据，名称冲突停止操作。账户及个人目录留存。

配置中的工作目录由现场明确设置，编译器及工具完整路径取自服务端既有工具配置。预览固定工具版本与路径，提交和登录执行期间继续复核版本。普通账户令牌实际请求读与执行权限，并在独立工作目录创建和删除随机探测文件。恢复管理员须能够离线认证且具有本机管理员成员资格。

即时登录的 Windows COM 边界采用单独的 C++17 SDK DLL，复用固定 MSVC 14.44.35207、SDK 10.0.19041.0，不新增第三方库。服务和业务逻辑保留五包 Rust workspace。V2 provider 使用 CredentialsChanged 与 GetCredentialCount 自动提交，通过 GetUserSid 关联目标账户。当前只支持 CPUS_LOGON。锁屏、多会话、RDP 和未知会话在预览中跳过。教学会话只有在网页确认工作已保存后才允许 WTSLogoffSession，管理员禁用在会话退出之后执行。

Provider 与服务使用固定长度、消息模式、拒绝远程的 SYSTEM-only 命名管道。双方核对内核提供的对端 PID、持续持有的进程句柄、SYSTEM SID、可执行文件路径和活动控制台。请求绑定设备、宿主实例、操作和目标 SID，5 秒单调期限，一次消费。服务或组件重启没有可重放的凭据授权。密码通过 DPAPI 与受保护目录保存，IPC 暂存和序列化缓冲清零，网络协议和事件只接受固定公开字段。Windows 原生密码 provider 持续可用。

服务以 `GetTickCount64` 检测心跳间隔及休眠恢复。网络读最多等待 5 秒，发送最多等待 3 秒，超过最近认证同步窗口后先撤回授权。明确断开立即进入恢复，窗口退出与账户恢复分别测量。断线后已经交给 Windows 的凭据提交可能继续建立桌面，客户端恢复账户可用性并保留该桌面。

恢复通过 MachineGuid、教学 SID 和原 flags 对照，只撤回本轮持久记录的禁用修改。外部 flags 不符合原值或本轮预期值时进入 recovery_failed，新启用被阻止。NetUserSetInfo 没有跨进程条件写入事务，读取与写入之间的外部管理员竞争及修改后又改回同值的情况仍需现场运维互斥。当前测试实现无法证明一个已遭管理员篡改的系统可信。

服务启动优先恢复残留，再建立网络连接。恢复失败持续报告并在离线重连间隔重试。`scripts/login-test.ps1 -Action Recover` 为独立测试机本地恢复入口，可在服务停止或损坏后以 SYSTEM 一次性任务调用保留的 agent 程序，读取相同恢复日志。该入口不依赖服务器。安装记录与账户记录缺失、SID 不匹配或复原后的旧记录都阻止新启用，人工先核对镜像及记录。完整卷复原、物理断电和机房辅助软件兼容性仍需真实镜像验证。


## 独立 Windows 10 实测修正

2026-11-11 在已授权的 WCCS-Login-Test 上发现，UAC 会将恢复管理员的交互令牌筛选为普通外观。恢复入口核验使用 TokenElevationType 和 TokenLinkedToken 检查完整管理员成员资格，关联令牌按拥有句柄释放。同一规则用于排除伪装成普通令牌的管理员比赛账户。[令牌提升类型](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ne-winnt-token_elevation_type) [关联令牌](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-token_linked_token)

Credential Provider 查询完成后，CredentialsChanged 会同步请求序列化。实测发现前一管道实例尚未结束，紧随其后的消费返回 ERROR_PIPE_BUSY。组件增加最多 200ms 的管道可用等待，保持一次性消费及 5 秒授权期限。修复后观察到真实比赛账户登录和 Windows 首次配置初始化。[自动提交接口](https://learn.microsoft.com/en-us/windows/win32/api/credentialprovider/nf-credentialprovider-icredentialprovider-getcredentialcount)

普通比赛会话无法直接打开 SYSTEM 服务进程或读取其令牌。会话程序启动前，仅向目标会话 SID 合并 PROCESS_QUERY_LIMITED_INFORMATION 进程权限，权限随服务进程退出失效。会话程序保持对端 PID 与真实映像校验，通过内核管道所有者 SYSTEM 和服务 Session 0 确认服务身份，避免要求普通账户读取 SYSTEM 令牌。管道 ACL 与启动进程防注入约束继续执行。凭据提供程序运行于 SYSTEM，仍核对双方令牌。[命名管道权限](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)

独立测试机实测账户恢复为明确断线 449ms、静默丢包加日期回拨 5079ms、首次服务崩溃后 SCM 重启 10093ms。等待窗口分别为 454ms、5081ms、249ms。连续崩溃耗尽 SCM 两次自动重启后，账户限制暂留，独立 Recover 工具已验证可恢复。上述单次数据分别描述账户和窗口行为，生产时延承诺仍须现场重复测量。

本轮保留临时禁用教学账户的受限测试方案。实际所有权冲突、账户禁用、错误凭据、工具 ACL、锁屏跳过、凭据提交中断线、恢复 flags 冲突、服务器关闭和 rustls 错误日期拒绝均已验证。原生密码恢复登录、已登录教学管理员的完整退出链、多会话/RDP、休眠及复原软件仍是生产采用前的实测条件。
