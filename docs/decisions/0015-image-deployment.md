# ADR 0015 统一镜像与 C 盘复原后的设备接入

## 状态

2026-11-16 实现，自动化与浏览器验证记录见 [任务记录](../tasks/image-deployment.md)。完整镜像、DPAPI、用户配置文件和复原软件需要两台实机补验。

## 背景

503-41 只有 C 盘，用户说明复原会覆盖系统盘和注册表，且各机器实际系统机器名唯一，通常为机房和座位号。母机普通账户首次欢迎与桌面准备需要由工作人员提前完成。

## 决定

- 运行时查询系统机器名，统一转为 ASCII 大写，以 SHA-256 截断值生成稳定设备关联号。MachineGuid 可随镜像重复。服务端根据真实来源 IP 执行原有座位核对。
- 每次从封装基线启动，生成随机注册材料和设备凭据。持久化完成后才安装、注册，重复启动复用已写入材料。C 盘复原清除这些运行材料后重新生成，管理员集中批准本轮凭据。公开机器名承担设备关联，随机凭据与人工审核承担认证。
- 镜像申请使用独立接口和迁移 013，复用原有注册窗口、管理员鉴权、CSRF、生命周期版本、请求去重和事件。批量审核原子提交，在线同名旧设备、冲突选择、初始化失败阻止批准。已有禁用状态保持，重新批准取消旧命令、撤销旧凭据代次并要求座位复核。
- 母机复用受控登录完成真实普通账户桌面探测，保存准备记录和工具路径。封装调用既有教学恢复、Provider 移除和服务卸载入口，导出清除设备绑定的账户模板，再清除安装目录内的逐机材料。清理进度存于目录外，可在部分删除后重试。
- 完整镜像保留 SAM、普通账户配置文件、工作目录、工具和 DPAPI 系统密钥。启动时验证账户 SID、所有权、权限、恢复账户认证、配置文件及工具访问，再将模板绑定到当前设备。模板和登录材料使用管理员/SYSTEM 私有 ACL。
- 公共配置、CA 与完整客户端载荷统一保存在母机镜像中。旧版公共支持包一并保留，确保现有服务端完整工具路径仍可访问。新增镜像身份与老式逐机身份兼容。
- 服务器离线时保持教学。恢复网络仅重试接入、报告状态，受控登录和等待继续由新的明确管理操作启用。

## 影响与边界

C 盘完整复原后的每轮接入需要管理端集中审核。机器重命名会生成新的关联号，管理员通过已有换机和座位核对处理。旧逐机部署第一次切换镜像身份也需要重新绑定座位，历史记录保留在原设备下。

封装入口处理专用安装及启动目录。工作人员需在母机统一清理另存的旧注册包、原始诊断和回收站副本。共享完整镜像包含受保护的普通账户登录材料，具有本机管理员权限的人可以干预系统，安全边界沿用 ADR 0011。

安装尚未达到可联网报告阶段时，失败记录位于本机启动状态文件。已经安装客户端的工具恢复、账户模板或服务启动失败可显示在管理端申请列表。任务计划程序按启动和失败重试，现场修复后可手动重跑该任务。

## 重新评估条件

实机出现重复系统机器名、Sysprep 重建账户或系统密钥、复原范围与完整镜像不同，或需要免审核恢复凭据时，重新评估设备认证和持久化方案。当前材料中不放共享设备认证令牌。

## 开机版本选择补充（2026-11-17）

已完成安装时核对机器、设备、服务及状态版本，开机直接使用已安装版本及对应支持包。升级保留完整支持包，中断升级先回退二进制事务。完整 C 盘复原仍恢复镜像基线版本，需更新并保存镜像以持久保留升级。实现与回归见 [稳定性记录](../tasks/client-deployment-stability.md)。
