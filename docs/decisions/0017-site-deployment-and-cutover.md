# ADR 0017 赛场部署、控制权与服务器切换

2026-11-25，本地实现，待 Linux 双机与机房镜像演练。适用于一个赛场、一个活动控制器和 200～300 台客户端。

## 部署边界

| 责任 | 持有的配置与状态 | 更换主机时的处理 |
| --- | --- | --- |
| 赛场入口 | 管理台、HTTPS API 与 WSS 共用一个 HTTPS origin，即协议、主机名和端口。信息中心维护解析或保留的服务 IP，Nginx 提供与入口匹配的证书 | 新部署优先使用稳定内网名称；已有 IP 镜像可以迁移原服务 IP。证书续期沿用客户端信任的 CA |
| Linux 控制器 | 成套服务二进制与 Web 资源、systemd 单元、本机配置、可信代理及独立 DOMjudge 连接配置 | 可预置在候选主机。启动前核对配置、静态入口与数据库；仅接管时启动调度 |
| PostgreSQL | 机房、身份代次、角色、比赛绑定、暂停座位、请求回执、资料及归档。运行中的浏览器会话在服务端内存 | 共享数据库时沿用同一份数据；迁库时核对最后写入点与恢复结果。DOMjudge 单独备份、核对暂停和提交状态 |
| Windows 镜像与逐机状态 | 镜像携带公开入口、CA 和程序。设备令牌、账户/策略恢复日志及实际会话属于该机 | 同一入口换主机沿用逐机身份。新入口使用新材料和注册审核；完整 C 盘复原后按既有镜像流程重新审核 |

## 活动控制器

正式服务入口先绑定监听端口，再在独立 PostgreSQL 会话持有数据库级排他 advisory lock，取得后才迁移、更新旧任务或启动后台工作。第二个新版进程连接同库时以 78 退出，随附 systemd 单元等待管理员处理冲突。业务连接短暂中断沿用原重连机制；控制器持锁会话一旦断开，本进程退出。systemd 对一般故障每 15 秒重试，数据库长时间关闭后仍可恢复。

每个独立数据库副本都有自己的锁。迁库、接管旧版控制器或网络分区时，运维人员须先隔离旧主机，并确认它不能再次向设备与 DOMjudge 发命令。就绪探针只提供观测，切换由管理员决定。自动复制、跨库选主和基础设施级隔离仍由现场部署方案承担。

## 凭据与授权

设备配置导入沿用基准版本、独占锁和原子写入。既有活动配置以当前有效入口为准，未配置的新身份可离线指定首个入口。清空地址进入待机时持久保存原绑定，恢复时校验规范化后的 origin。旧版离线记录可从逐机材料找回已知入口；两处都没有可识别来源的历史记录需要重新注册。本机 `--setup-status` 可查看 `credential_origin`。新格式的离线绑定记录在降级到旧 agent 前须恢复原入口，或使用经核对的部署备份。

控制授权限定于已认证的 WSS 连接。首次交换在同一个事务中撤销该机旧等待与登录授权、替换连接并读取新状态。旧客户端首帧携带的上一条回执不计入新连接。新客户端也会丢弃旧服务端在首轮轮询返回并持续重发的既有命令。它从新连接开始核对命令序号，恢复库里较小的序号仍可用于**新授权**。账户、窗口和策略恢复沿用本机日志与单调超时。教学期间尚无命令时，失联状态为教学待机、桌面状态未知。

已知本机 Administrator 密码的人员仍能改变系统服务、信任库、程序或本机材料。入口绑定保护正常配置导入；机器 ACL、SYSTEM 和本机日志用于普通账户隔离和事故恢复。设备撤销、角色与机房授权、重新注册审批和操作审计由服务端执行。母机封装前移除逐机凭据；服务器及 CA 私钥、数据库备份和 DOMjudge 密钥分别保管。

## 不可用时的管理语义

| 观察 | 值班操作 |
| --- | --- |
| `GET /api/health` 正常，`GET /api/ready` 返回 503 | 进程可达，独立数据库探测未通过。检查数据库连接、schema 和只读状态 |
| 两项探测均无有效响应 | 从管理机核对名称解析、证书、代理、控制器与数据库。保留最后快照并标为过期 |
| 选手机失去控制连接 | 本机撤回当轮限制、保留当前会话和文件。重连后逐机核对教学状态与恢复失败记录，新的管理操作才能重新启用控制 |
| 管理请求响应不确定或切换前已有任务 | 按原请求号核对持久结果、设备回执及 DOMjudge 实际状态。文件分发、归档和维护各有独立日志，按对应业务恢复，避免重复提交 |

就绪检查有四秒总期限，通过独立连接读取当前 schema 和数据库只读状态。它不验证业务表的全部授权、每个客户端或 DOMjudge。登录页与已登录管理台均可从“服务入口诊断”分别检查进程和数据库。具体切换、回退步骤见[现场操作说明](../tasks/server-cutover.md)。
