# 需求基线

更新日期为 2026-11-16。来源为项目初始化讨论及其后对 Linux 服务端、原生客户端和管理界面的要求。

## 统一镜像部署要求（2026-11-16）

用户确认机房各台机器的实际系统机器名各不相同，通常采用“机房-座位号”，首台记录为 503-41。客户端直接查询运行中的 Windows 系统机器名。服务端以已核对的机器名关联长期设备记录，结合实际来源 IP 核对座位，硬件信息用于冲突与换机检查。注册凭据继续独立管理，名称重复或信息不一致时进入管理端处理。实现应覆盖 C 盘复原后的原设备关联，避免每次复原都新增孤立设备记录。

用户本轮进一步说明复原方式应为恢复整个 C 盘，注册表随统一镜像恢复。当前按整盘复原设计，覆盖只有 C 盘的 503-41，不依赖目录排除或逐机保存初始化基线。复原软件型号与实际行为待现场验证。母机需要提前完成普通账户首次初始化并随镜像交付，克隆设备的注册与重启后关联由软件和服务端审核流程处理。实现状态见 [镜像开发记录](tasks/image-deployment.md)。

用户再次明确机房通过统一镜像分发客户端。管理员在母机配置一次客户端、服务器地址及 CA，再制作并分发镜像。各机器首次启动时自动初始化独立身份并提交注册申请，管理员在管理端集中核对和批量审核。逐机身份初始化由软件完成，常规部署应免去逐台编辑配置、生成令牌和复制文件的人工步骤。安装时服务器地址尚未确定的情况继续支持，后续通过统一配置分发补齐。

镜像封装需处理母机身份、设备凭据、目标绑定和账户/策略恢复记录。克隆机器的 MachineGuid 可能重复，初始化与冲突处理需要覆盖该情况。正常重启及复原软件重启后的设备关联需保持可恢复，持久化位置依据实际复原条件验证，覆盖现场只有 C 盘挂载的机器。教学期间服务器离线时，初始化等待保持教学可用。

2026-11-16 首台实机测试安装尚未固化到镜像。用户预计重启复原会撤销本轮安装，本轮需先完成母机封装并保存完整镜像，再验证重启自动安装和集中重新审核。正式多机分发沿用上述封装和逐机初始化要求。

统一镜像封装、首次启动自动初始化和配套批量注册审核已实现，继续复用原单机安装、诊断和教学恢复入口。C 盘完整复原后自动生成新凭据，管理员集中批准接入；机器名关联同一镜像设备，来源 IP 用于座位复核。母机账户及完整镜像行为仍待两台实机验证，软件与现场证据见 [任务记录](tasks/image-deployment.md)。

2026-11-16 首台实机进入新比赛账户时出现 Windows 首次登录欢迎界面，用户要求提前自动完成初始化。正式流程需由工作人员在赛前统一触发账户准备和首次桌面初始化，管理端按实际桌面确认标记就绪，选手使用已完成初始化的账户。覆盖失败重试、超时、复原软件重启及配置文件被清理后的重新初始化。批量准备复用现有受控登录与维护入口，已补充桌面/Shell 探测、持久准备记录及镜像模板导入。首台机器已通过旧版登录流程完成一次实际初始化，新镜像的欢迎界面消除与配置文件恢复仍需现场验证。

## 部署与服务器切换（2026-11-25）

2026-11-25 用户要求从系统架构层处理部署、管理、服务器切换、防护和服务不可用。当前工程选择为稳定赛场入口、人工接管和数据库级单活动控制器。部署到新信任域时重新注册，控制中断后需新的明确管理授权。现场 DNS 或服务 IP 能否迁移、两机数据库同步点与可接受的停赛时长待运维演练确认。[部署与接管决策](decisions/0017-site-deployment-and-cutover.md)

## 部署后的客户端稳定性（2026-11-17）

用户要求部署后避免客户端大幅变更。部署前补齐本机会话电源恢复、整卷清理容量、镜像开机与升级恢复，并保持旧任务及旧客户端能力兼容。后续名单、工具路径、比赛安排和竞赛脚本优先通过已有服务端配置及分发入口更新。本轮现场验收暂缓，开发侧实现与验证见 [客户端稳定性记录](tasks/client-deployment-stability.md)。

## 现场部署窗口约束

2026-11-12 用户说明赴机房演练机会有限，希望控制在两次以内。实施以最多两次现场窗口为计划目标，将 Linux 部署、功能闭环、协议与文件故障回归、安装与回退工具及模拟容量验证前移。首次现场窗口用于代表性机器和真实网络、镜像适配，第二次用于批量部署及全流程验收。该安排为计划，实际现场验证尚未完成。

现场前争取由信息中心提供脱敏环境报告、镜像或同配置测试机、复原软件信息、网络规则和 DOMjudge 配置条件，具体可获得性待确认。计划不依赖额外的常驻人员或远程访问能力。现场发现问题后带回可复现证据修复，第二次仍有影响教学恢复、登录或比赛正确性的未解决故障时保留失败状态，根据影响调整上线范围或部署日期。验证安排见 [两次现场窗口计划](validation.md#两次现场窗口计划)。

2026-11-13 用户决定清理虚拟化验证环境，后续直接推进开发和首次实机测试准备。现场前执行自动化回归、Linux 联调、模拟容量与部署材料检查。Windows 原生重启、长期显示、现场账户和复原软件等剩余项目安排到首次实机验证。

首次实机准备增加成套离线客户端、逐机身份初始化、明确机器名/MachineGuid 核验、机器级 CA、安装升级回退、本机教学恢复和脱敏证据导出。开发机验证限定到独立临时目录和只读采集，账户、Credential Provider、系统服务、机器证书和策略实际修改在显式指定的现场目标执行。现场流程与成功判据见 [操作说明](tasks/offline-client-field-guide.md)。

## 设计建议与范围约定

- 服务器采用单体部署，Windows 服务与用户会话程序分工，详见架构及 ADR。
- 在用户给出的语言范围内，当前项目方向选择两端 Rust，管理界面使用 React + TypeScript + Vite。此实现选择及后续验证条件见 ADR 0002。
- 选手命令以脚本形式独立发布，WCCS 负责版本固定、Windows 适配、配置、分发与检查。复用和自行实现按维护成本与兼容性选择，见 ADR 0003。
- 工具选择与路径配置归服务端管理，客户端执行收到的配置快照。工具、解释器、IDE 和竞赛脚本均按完整文件路径检查，未配置、文件缺失与权限不足分别报告，见 ADR 0004。
- 500 个模拟客户端用于容量余量验证，该数字为项目设计目标。
- 文件收集是赛后流程的可配置步骤；每场比赛明确收集范围或选择跳过，并记录结果。
- 统一资料下发满足当前资料需求。内部资料站可在后续实际需求出现时评估。
- 2026-11-16 用户决定文件分发采用服务器 HTTPS 直传，取消 P2P。机间隔离保持现场既有安排，传输通过服务器限流、并发控制、校验与续传完成。
- 网络异常时退出 WCCS 控制并撤销本轮可恢复限制，保留当前会话、程序及文件。连接恢复后上报状态，新的管理操作才可重新启用。该规则依据连接状态与单调计时，比赛日历安排另行设计。
- 2026-11-17 用户确认比赛暂停须同时暂停 DOMjudge 计时、提交与选手桌面。恢复须核对两端实际状态，部分失败需显示原因和恢复入口。

## 机房座位表需求补充

2026-11-10 用户明确要求可编辑各机房的矩形电脑座位表，各机房大小可不同，座位编号连续，并提供方便的 IP 绑定方式。编号方式由管理员自行设置。

- 每个机房独立维护名称、行数、列数、座位位置及连续编号。
- 编号规则可配置，预设按行、按列、蛇形，并支持自定义排列。起始号和遍历起点作为可配置项，默认值在页面可见。
- 自定义编号允许在草稿中逐格修改，保存前检查编号数量、连续性及重复项，定位错误座位。
- IP 绑定提供批量顺序填充、表格粘贴和单座位编辑。批量操作先预览座位号与 IP 的对应关系，再持久化。
- 座位的稳定身份关联物理位置及 IP。重新编号时保留该位置的 IP，调整尺寸时显示保留和移除位置及其绑定影响。
- 页面显示座位预期 IP、匹配到的设备、在线状态及冲突。设备注册和请求认证继续使用独立凭据。

本节要求已在 M2 机房座位表切片落地，Windows 开发机、PostgreSQL 与真实浏览器闭环通过。默认离线设备保留占用，地址变化和重复占用需管理员核对。座位工具检查跳过离线、冲突、未注册及当前全局配置范围外目标，详见 [实施与验证记录](tasks/m2-room-seating.md)。

## 设备注册审核与凭据生命周期

M2 已交付管理员显式开启 / 关闭注册窗口、申请批准 / 拒绝 / 过期、设备启用 / 禁用 / 撤销、凭据轮换及重装重新授权。设备身份与认证独立于 IP，禁用保留占用，撤销释放占用，排除占用不改变凭据。所有管理动作带基准版本和持久请求编号，结果与历史可查询。

逐设备材料入口保留。客户端预持久化候选凭据后切换，重试及进程退出可恢复，旧凭据在切换或撤销后停止普通访问。重装采用新材料和独立目录，管理员核对申请关联号与来源地址。实现、Bearer 完整复制边界及验证见 [生命周期记录](tasks/m2-device-lifecycle.md)。

## 选手名单与座位分配

## 操作员角色与全局事件

M2 已实现持久操作员账号、显示名、三类角色、启用/禁用、机房范围和密码重置。配置管理员首次迁入，原登录和历史操作者兼容。权限版本变化使旧会话失效，后端校验读取、预览、写入、结果和历史，最后一个有效管理员受到保护。

管理员承担机房/IP、全场名单、全局工具配置和凭据管理，操作员在授权范围启停设备与重查，只读查看员查询授权数据。事件可按时间、人员、类型、设备、机房、比赛、请求与结果过滤，范围固定为当时证据，历史未知字段明确展示，支持稳定分页、详情和业务关联。流程、API 范围及证据见 [操作员与事件记录](tasks/m2-operator-events.md)。

管理员应能区分设备原位更换与选手换座，核对批量操作中筛选外的目标，分别看到命令受理与执行状态。WCCS 比赛与 DOMjudge 比赛显式绑定，恢复整场计时必须覆盖未结的暂停座位。恢复任务按完整批次核对，不得从截断的历史推断全部成功设备。见[现场操作与验收](tasks/admin-workflows.md)。

## M2 等待控制与教学恢复

2026-11-12 等待加固要求正式受控模式关闭 Esc、Alt+F4 和本地关闭消息入口，覆盖普通桌面任务切换与 Win 组合键，并对目标比赛账户应用可恢复的任务管理器策略。开发预览保留便捷退出。正式模式要求普通比赛账户已准备、SID 与桌面确认一致。状态回执同时核验前台和输入桌面，恢复失败可从管理页和本机日志定位。策略原值持久保存，正常解除、失联、会话变化和服务重启均撤回本轮限制。实现、实际虚拟机矩阵和仍可退出控制的路径见 [等待加固记录](tasks/m2-waiting-hardening.md) 与 [ADR 0012](decisions/0012-waiting-hardening.md)。

2026-11-11 已接入 Windows 服务宿主、设备 WSS、用户会话命名管道和 `#/waiting` 批量控制。管理员及授权操作员选择比赛/座位后核对固定设备与选手快照，再显式进入或结束等待。页面分别显示接收、执行、历史完成与当前实际状态，离线状态标为未知。命令期限默认 900 秒，允许 30～3600 秒，现场安排规则继续在 M3 实施。

服务端上线与客户端离线启动保持教学待机。服务端或宿主重启取消旧等待授权，重新进入要求新预览。无会话、IPC 拒绝、屏幕或进程异常保留失败，网络失联后短租约结束窗口。真实前台宿主与浏览器闭环通过，SCM/Session 0、跨用户权限、Linux/WSS 证书和现场条件见 [等待控制记录](tasks/m2-waiting-control.md)。

## 比赛账户切片目标

2026-11-11 将 REQ-02 提前实施。教学沿用 ENV-10 的账户，比赛专用普通账户、即时登录与离线恢复已有独立 Windows 10 单机真实闭环。管理页面选择电脑、预览当前状态、显式准备并登录，确认真实桌面后衔接等待控制。开机自动登录移出本轮目标。教学时服务器关闭应正常使用，比赛中确认失联后自动退出控制并撤销本轮限制，保留当前桌面和文件，恢复失败可由现场运维处理。临时禁用教学 Administrator 和独立本机恢复已实测，完整教学会话退出、恢复管理员图形登录和机房镜像继续补验，生产采用条件见 [ADR 0011](decisions/0011-contest-login-offline.md)。

2026-11-12 补验通过恢复管理员图形登录、既有教学管理员会话经明确确认退出、旧管理员交互进程终止及比赛账户接续登录。多会话明确跳过，锁屏后的比赛账户解锁继续单独实施。机房镜像、RDP 和复原软件条件仍需验证，详见 [等待加固记录](tasks/m2-waiting-hardening.md)。

同一切片重新评估本机管理员修改 server、停止服务、结束会话进程及访问设备凭据的影响，记录实际可阻止、可检测和可恢复的范围。既有文件 ACL、IPC 与 SYSTEM 进程保护的普通权限测试证据不能推导出对本机管理员的防干预保证。账号策略如需改变，应作为明确方案交由用户决定。


本轮交付入口、操作说明与证据见 [比赛账户任务记录](tasks/m2-contest-login.md)。服务或系统重启使旧授权失效，恢复与重新启用串行，未恢复设备不能启用。机房复原造成账户及各卷记录不一致时，旧记录不得恢复控制。窗口租约与账户恢复分别记录时延。主动断网解除本机限制为已确定产品取舍。

## machine-tools 运维能力

2026-11-12 纳入本机配置诊断、版本化文本/文件快速配置、物理座位识别、动态健康与版本筛选、完整等待展示及固定桌面维护模板。正常入口、实现与分层证据见 [对齐记录](tasks/machine-tools-alignment.md)。

教学离线允许保存连接配置，待联网项目与部分成功分别显示。诊断成功依据对应通道真实回执。座位声明与网卡核验接入现有 IP 核对流程。主动设备识别允许取消和单调到期，正式等待继续使用既有明确授权与恢复语义。

健康数据必须带采集时间和可用性，离线或超龄标为过期。展示包含开始时间、倒计时、服务器时间样本/RTT/偏差、分别标明来源的 WCCS 与 DOMjudge 状态，以及校徽摘要和身份绑定缓存。展示缓存不得恢复控制授权。

桌面入口、普通账户工作目录和版本化脚本包使用固定模板，具备目标/权限/能力预览、跳过原因、逐机阶段、结果与事件。任务和必要旧值先持久化，断线补报、重复派发、系统重启及部分失败具有明确恢复规则。实现边界见 [ADR 0014](decisions/0014-machine-tools-alignment.md)。网络参数写入与二维码不纳入当前核心文本/文件流程；原生环境验收未通过前不视为生产可用。

2026-11-18 补充：赛后整卷恢复仅授权逐机核对过身份的 D 盘。比赛暂停由原在线连接按短租约持续，断线解除，重连需重新授权。操作与兼容条件见 [比赛控制与恢复决策](decisions/0016-contest-control-and-recovery.md)。
