# 管理员操作走查与改动（本地，2026-11-18）

管理台服务于多机房值班人员。判断操作是否完成，要分别看物理座位、实际设备、选手分配、评测账号和远端回执，不能用一个“成功”代替这些结果。

| 走查发现 | 现在怎样操作 |
| --- | --- |
| 导航按功能堆放，管理员需要先记页面名称 | 从“现场巡查”看座位和设备；“赛前布置”按注册、机房、名单、评测到分发排列；等待、比赛安排和恢复放在“比赛与收场”。 |
| 过滤机房后，原来选中的其他机房座位仍会被操作 | 座位选择栏显示筛选外数量，按钮明确为追加；用比赛下拉框切换比赛时清空座位选择。预览仍是服务器的实际执行范围。 |
| 未保存的 IP 与正在运行的设备混在同一格 | 编辑时标出已生效 IP，禁止用草稿发检查。保存影响默认只列变动；粘贴内容先应用到草稿或清空，才能保存。 |
| 切换机房或重载会无提示丢草稿 | 有改动时明确确认，取消即可回到草稿；页内导航保留编辑器，浏览器离开时请求离开提示。草稿未持久化，不能当备份。 |
| 故障机在数百行设备中不好找；正常设备也能被重复“核对” | 在原位换电脑区按机房、座号、机器名或地址搜索，支持只看异常。新地址与排除恢复分开，正常设备无需核对。排除前确认机器、IP、位置和所选比赛的占座人；无变化的核对不推进地址版本。 |
| 换电脑、换座和交换选手容易混淆，换座后评测账号仍可能认旧 IP | 人不动走“原位换电脑”；人要动在名单选“移到空座”“与另一名选手交换”或“解除分配”。保存后带受影响人员进入评测核对；已记录绑定与座位 IP 不同时提示待核对，不自动改账号。 |
| 账号同步和暂停比赛分别手填远端 ID，可能操作另一场 | 在 DOMjudge 账号页读取远端列表，按名称和编号确认一次。联动和账号同步沿用同一绑定，服务端分别在预览、提交和执行时复核。 |
| 少选一个机房，桌面只解除一部分，评测却可能全场恢复 | 暂停可能产生影响前先记下座位，多次暂停取并集；恢复时带出本轮范围，开始、恢复和结束不能漏掉这些座位。故障或重启保留记录，不因超时或客户端断线删除座位。整场动作与所选桌面的范围分别提示。 |
| 命令已受理但刷新失败，值班人员容易再次提交 | 写入成功与刷新失败分别反馈；未收到明确写响应时提示结果待核对，可按原请求编号查事件。受理不代表逐机执行成功。 |
| 恢复历史只取最近 500 条，批次后续步骤可能漏机 | 逐机历史可按批次请求编号查找；下一步向服务端取当前授权范围内该批完整结果，仅勾选成功设备并报未进入下一步的数量。初检可按机房追加设备，归档、清理及重启仍需单独预览。 |

## 本地验证

- Windows 固定工具链：`scripts/check-rust.ps1` 的构建、格式、Clippy、常规测试及 Provider 构建通过。`npm --prefix web run check` 通过，含 37 项前端测试。
- 独立回环 PostgreSQL：HTTP 集成测试 `--ignored --skip concurrent_control_preview_commit_and_reconnect` 22 项通过。其中 300 台 × 两批产生 600 条记录，最近列表只有 500 条，按第一批编号仍返回 300 台。另以临时 schema 验证 19 → 20：历史暂停 A/B 后仅恢复 A、取消暂停 C，迁移只保留 B。
- 单独运行 `concurrent_control_preview_commit_and_reconnect`，300 个模拟客户端、10 秒采样通过。不是 300 台实机或长时间演练。
- Edge、真实本地 WCCS、独立数据库 schema、模拟 DOMjudge HTTPS：验证草稿阻止向旧设备检查、从评测列表确认绑定、少选暂停座位被拒绝、恢复下一步按批查询。两位合成选手交换座位时注入写成功后的状态刷新失败，页面提示不要重提，并能带两名选手进入评测核对。
- `python -m unittest discover -s scripts/tests -v` 28 项通过。未操作部署服务器、现场设备或真实参赛数据。

## 升级与现场复核

- 本地数据库版本为 20。上线须成套更新服务端和 Web，停止安排新任务、备份数据库并验证可恢复。旧服务端不读取版本 20。此次没有部署。
- 不从历史手填的比赛 ID 自动建立信任关系。升级后先绑定比赛，再试账号预览和控制预览；迁移按远端比赛及座位保守保留可能尚未解除的暂停。不在进行中的正式比赛中做首次升级。
- 控制掉线仍按原策略释放本机限制。服务端的待恢复清单是重新开赛的核对条件，不是对离线客户端的持续控制；不能通过取消勾选绕过故障机器。若设备永久损坏，应先按原位换机核对，无法取得所需回执时保持暂停并由裁判处置。
- 代表机演练：一人改座、一对选手互换、同座更换设备；两个机房暂停后尝试只恢复一个；网络中断后按编号核对；分三批完成归档并核对成功、失败及待人工处理数量。真实评测、机房网络及管理员独立操作耗时仍需验证。
