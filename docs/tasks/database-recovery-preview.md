# 数据库恢复与等待预览阻塞修复

日期为 2026-11-12，承接 [xcpc-tools 审查](xcpc-waiting-review.md) 的两项服务端问题。沿用当前分支和已有未提交改动，架构决定见 [ADR 0013](../decisions/0013-database-recovery-preview.md)。

## 实现

`database.rs` 封装按需重连、三秒握手上限和一秒失败冷却。所有原业务数据库入口传播连接获取错误，WebSocket 退出清理允许数据库暂时不可用。重连沿用完整配置和应用会话，事务失败由原请求编号的持久去重机制处理。

等待预览使用独立只读、可重复读连接。鉴权和目标数据属于同一快照，提交继续核对最新状态。计划中的四类逐座位查询合并为集合读取，500 个已绑定座位的计划查询从最多 2006 条降为十条，输出顺序、旧命令身份及跳过原因沿用现有语义。

## 回归覆盖

- 单元测试用仅接受 TCP 的本地端口模拟握手挂起，验证三秒超时、503、快速失败冷却，以及取消连接尝试后的冷却。
- PostgreSQL 集成精确终止测试实例的业务连接和预览连接，验证原登录会话恢复、并发访问成功、连接 PID 更换、server_epoch 延续、同请求回放结果一致且只产生一条命令。
- 在事务已修改数据后终止其连接，核对提交失败和数据库回滚。恢复后重复原业务请求，仍取得相同回执。
- 恢复后的 WebSocket 继续完成鉴权与续租。更换客户端实例后，旧命令被取消。
- 使用隔离 schema 的 500 个合成座位、选手、设备和在线状态，通过表锁故意阻塞预览的选手查询。阻塞期间完成八次真实 WebSocket 往返，并检查管理会话查询可用。
- 阻塞期间修改比赛版本，验证预览仍返回完整的原快照，提交旧 token 返回 409。重新预览后撤销操作者版本，旧会话提交和预览均返回 401。
- 既有七项数据库综合测试继续覆盖跨机房权限、等待状态、账户准备、连接绑定、身份变化和历史去重。

## 实际验证

环境为 Windows 开发机、固定 Rust 1.99.1 / MSVC 14.44.35207 / SDK 10.0.19041.0，以及回环地址上的 PostgreSQL 18 测试集群。

| 检查 | 结果 |
| --- | --- |
| `pwsh -NoProfile -File scripts/check-m2.ps1 -ServerConfig local/m2/server.json` | 发布构建、格式、Clippy、68 项 Rust 常规测试、9 项 PostgreSQL 综合测试、34 项前端测试及生产构建通过 |
| 最终 Rust 与数据库复核 | `check-rust.ps1` 通过；两项新 PostgreSQL 回归连续五轮通过，随后全部九项数据库测试再次通过 |
| Linux 交叉类型检查 | `cargo check --locked -p wccs-server -p wccs-protocol --target x86_64-unknown-linux-gnu` 通过 |
| 仓库检查 | 159 个文件、14 项 Python 回归及工作区 / 暂存区 diff 检查通过 |
| 浏览器数据库停机恢复 | 独立 8789 / database_fixes_browser 实例，停止 PostgreSQL 后显示连接中断和数据库暂时不可用，重启 PostgreSQL 后原登录页面恢复服务已连接，WCCS 进程 PID 及启动时间连续 |

完整检查日志为 `artifacts/database-fixes-m2.txt`，最终 Rust 复核为 `artifacts/database-fixes-rust.txt`，重复故障注入及 Linux 类型检查为 `artifacts/database-fixes-repeat.txt`。浏览器验证使用独立回环服务，结束后关闭本轮服务进程并删除其合成 schema。

五轮测量中，连接被终止后恢复查询成功耗时 71～146 毫秒。连接驱动关闭通知与请求存在时序窗口，首个请求可以收到 503，回归按五秒上限核对后续请求恢复。500 座位预览阻塞期间每轮八次 WebSocket 往返，p50 为 214～217 毫秒，最大值为 219 毫秒，包含服务端原有每轮 200 毫秒节流。以上为本机回环测试观测值。
