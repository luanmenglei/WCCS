# M2 矩形机房座位表与 IP 绑定

日期为 2026-11-10。状态为 Windows 开发机闭环已实现，Linux 与现场网络验收待补。

## 当前实现与用户要求

本轮从工具配置切片继续开发，核对本地 `416bc1f`、`d8631ac`、`9c1e45d`。开始时 README、需求、架构、路线图、验证及本任务记录已有机房需求补充，全部保留并同步实现状态。工作分支为 `feat/room-seating`，由单个主任务完成。

用户要求每个机房有可编辑的矩形座位表，各机房尺寸独立，座位编号连续，并能方便地批量绑定 IP。用户进一步明确编号方式应可自行设置。

## 页面流程

1. 创建机房，填写名称、行数和列数，预览矩形座位网格。
2. 设置起始座位号及编号规则。提供起点选择、按行、按列、蛇形和自定义排列。初始值为从 1 开始、左上角起、按行递增，管理员可修改。
3. 自定义排列可直接编辑各位置的显示编号，保存前标出重复、缺号和数量错误。每间机房的完整编号集合必须为起始号至起始号加座位数减一。
4. 通过批量填充、粘贴表格或单座位编辑设置 IP，预览后提交。
5. 客户端认证并上报后，显示对应座位的在线状态、实际来源地址和工具检查结果。未知地址及匹配冲突进入待核对列表。
6. 在座位图选择整间机房或部分座位，展开并展示实际设备目标，再发起工具检查。

座位卡片显示编号、IP 和文字状态。点击后编辑单座位，整间机房可切换到表格编辑视图。大型座位图支持滚动，保留行列标识。

## IP 批量操作

| 方式 | 操作 |
| --- | --- |
| 连续地址填充 | 填写起始 IPv4、步长和遍历顺序，为整间机房预览生成结果 |
| 座位号/IP 两列粘贴 | 从已有表格复制两列，按座位号定位；支持非连续地址 |
| IP 矩阵粘贴 | 将与机房行列对应的 IP 表格粘贴到网格，按位置映射 |
| 单座位修改 | 点击座位后设置或清空预期 IP |

批量填充的遍历顺序可选座位号递增或明确的行列顺序，预览列出最终映射。处理地址越界、无效格式、数量不匹配、重复座位号、重复 IP 和覆盖已有绑定。粘贴矩阵中的空白单元格在预览中明确标为未配置，提交前显示将清空的绑定。

IPv4 为本轮已实现的配置地址格式。IP 作为服务器端座位配置保存，设备认证继续由独立注册身份及凭据承担。

## 数据及并发边界

- Room 保存稳定 ID、名称、行列尺寸、起始编号、编号规则和编辑版本。
- Seat 保存稳定 ID、机房 ID、行列位置、显示编号和预期 IP。机房内位置及编号唯一。
- 重编号只更新显示编号，IP 及业务关联通过稳定座位 ID 保留在对应位置。
- 改变行列尺寸先显示位置保留、增加和移除清单。被移除位置上的 IP、设备及后续选手关联纳入影响预览，服务端再次校验。
- 机房编辑与批量 IP 绑定具备基准版本、持久请求编号和原子事务，重复请求幂等，多管理员冲突返回当前版本。
- 第一阶段按服务端可见的地址空间检查跨机房 IP 冲突。若现场采用重叠地址或 NAT，则需要可验证的网络范围标识，列为现场依赖。
- 设备认证后根据可信来源 IP 匹配唯一座位。来源地址与客户端报告字段分别保存，反向代理只信任明确配置的代理。
- 地址变化、同 IP 多设备和一个设备竞争多个座位均展示待核对状态，核对操作记录审计。
- 已有设备迁移为未分配设备，已有配置版本与检查结果按原身份可查询。

## 已落地的数据和匹配语义

- `002_seating.sql` 将版本 1 原子迁移到版本 2。首次启动创建版本 1 后立即迁移，后续启动识别版本 2，未知版本拒绝启动。迁移保留设备凭据、配置、目标任务和历史结果，已有设备观察地址初始为空。
- 每间机房上限 500 个座位，每边 1～50，上限 100 间。起始号为 0～1000000，默认 1，左上按行。预设按行、按列、按行蛇形均支持四个角作为起点。自定义排列必须覆盖完整连续整数集合。
- 座位使用随机稳定 ID，数据库对机房内位置、编号及全场非空 IP 施加唯一约束。保留位置通过 upsert 更新编号和 IP。移除后重新增加的位置获得新 ID。
- IP 和尺寸编辑先生成服务端预览，展示旧位置、编号、IP、原关联和新匹配设备。确认携带预览摘要，绑定或在线状态变化导致摘要不符时要求重新预览。失败不写入部分布局。
- 设备通过独立 Bearer 凭据认证后，心跳写入连接对端 `peer_ip`、可信观察地址 `observed_ip`、来源 `address_source`、客户端声明 `reported_ips`、此前观察地址及地址版本。旧客户端未提供 `reported_ips` 时按空列表处理。当前 Windows 入口报告面向服务地址的路由所选本地地址，结果仅供核对。
- 当前关联由持久化座位 IP 与设备最新观察地址计算。首次有效认证心跳自动参与匹配。地址变化撤销旧位置匹配并设置 `needs_review`，新位置显示冲突。管理员按地址版本核对后恢复匹配。
- 同一 IP 的多个未排除设备始终显示冲突，离线设备也保留占用证据。管理员可排除设备占用或恢复匹配。排除持续有效，地址变化后也需管理员显式恢复。设备身份和历史结果保留。
- 未知地址、无对应 IP、已排除设备出现在地址核对表的“未分配”项。核对按钮仅确认当前观察地址，预期 IP 在座位编辑器中修改。核对与排除均记录持久请求、版本和审计。
- 保存、核对和发起检查复用 Cookie、Origin、CSRF 鉴权。数据库配置头行锁串行化管理写入和地址观察，兼顾多服务进程。请求编号全局唯一，相同内容返回原结果，不同内容返回 409。座位保存使用机房版本，地址核对使用地址版本，检查使用全局配置版本及目标摘要。

## 工具检查入口

座位页使用独立的 `seating/check-preview` 和 `seating/check`。选择整间机房或单个已保存座位后，展开实际设备与逐项处理结果。

| 目标状态 | 处理 |
| --- | --- |
| 唯一在线设备且属于当前全局配置目标 | 创建当前配置版本的新检查任务 |
| 未绑定 / 尚无注册设备 | 跳过，显示未注册或未匹配 |
| 离线 | 跳过，等待上线后重新预览 |
| 冲突 / 地址变化待核对 | 跳过，先在地址表核对 |
| 全局配置目标范围外 | 跳过，先在工具配置页发布完整目标集合 |

本入口只更新实际执行设备的期望任务。机房保存与地址核对不写工具配置或任务，目标集合沿用 ADR 0005。逐项展开结果随请求响应持久保存。已有工具发布仍会替换完整目标集合，重新检查仍要求属于该集合。座位操作不会将机房范围隐式转换为新的全局配置范围。

## 反向代理配置

部署配置新增可选 `trusted_proxies`，默认空数组，元素为精确 IP 地址。直连使用 TCP 对端，忽略转发头。仅当对端显式受信任时读取一个 `X-Forwarded-For` 头，从右向左跳过已信任代理，取首个不受信任地址。无头、重复头、非法地址或超过 16 跳均记为未知来源。IPv4-mapped IPv6 归一为 IPv4，座位配置首轮使用 IPv4。

示例配置片段使用合成地址。

```json
{"trusted_proxies":["127.0.0.1","192.0.2.10"]}
```

代理必须覆盖客户端伪造头或正确追加真实对端，并限制直接访问后端。真实代理链、HTTPS 证书、跨 VLAN、NAT 与重叠地址空间需要现场拓扑验证。当前自动化测试通过真实 HTTP 注入代理头验证信任算法，尚无真实代理部署证据。

1. 在“机房与座位”创建机房，填名称和行列，点击“应用尺寸到草稿”。
2. 设置起始号、规则及起点，点击“应用编号规则”。逐格修改编号自动切换为自定义排列，错误格显示文字与高亮。
3. 展开“批量绑定 IP”，设置起始 IPv4、正整数步长及顺序，或粘贴制表符分隔的两列 / 矩阵。核对覆盖、清空及保留映射后应用到草稿。单格可直接填写或清空 IP。

5. 运行独立 Windows 客户端，查看座位状态、检查结果及地址核对表。可选择紧凑、标准、放大视图，座位表支持横向和纵向滚动。
6. 选择单座位或整间机房，点击“预览检查目标”，核对实际设备与跳过原因后发起检查。客户端回传后更新逐项结果。

## 自审与后续条件

- 修正迁移入口，避免每次启动都向版本表重新插入版本 1。
- 服务端独立校验矩形位置、数量、编号连续性及预设规则，前端同样提供逐格反馈。越界位置的错误消息采用宽整数运算，覆盖最大整数输入。使用延迟唯一约束支持编号和 IP 在一个事务内交换。
- 预览摘要包含原关联和新匹配设备，保存时重算，避免预览后地址变化导致移除影响失真。
- 检查目标在提交事务内重新展开。冲突、离线及范围外目标明确跳过，冲突预览列出全部候选设备，持久保存实际处理集合。
- 前端请求编号在刷新成功后才清除，提交成功但刷新失败时保留重试编号。未应用的尺寸输入会禁用保存并提示应用草稿。
- 默认保留离线占用，需要管理员明确核对换机。机房范围、代理信任及全局配置目标的实现选择见 [ADR 0006](../decisions/0006-m2-room-seating.md)。

本轮复查 WSL 仍提示未安装，未发现 Docker / Podman 命令或 SSH 配置。实际 Linux 原生构建与运行、HTTPS 代理及证书、跨 VLAN / NAT / ACL、Windows 10 机房镜像和复原后身份恢复尚待环境。现有回环设备实测不能给出这些环境的结论。500 客户端及 300 座位持续更新负载仍按 M6 验收。
