# M3～M5 单机验收现场说明

本轮 Windows 部署排除 503-41。具体流程、目标机器均待确定。本页列出选定代表机后的功能验收项目。

## 验收环境

在已按现场方案安装客户端的代表机上核对版本和诊断结果。只有选用既有母机升级路径时，才使用为该机重新生成的专用包，并按同包 READ-ME.md 核对目标。

## 赛前准备

1. 打开本场 WCCS 管理地址，核对选定的代表机在线、座位和选手资料正确。若是镜像首次启动或 C 盘已复原，在注册审核中核对机器名、IP 和本次申请，再批准新凭据。
2. 在比赛账户页面选择这台电脑。需要禁止可移动存储和普通用户软件关机时勾选对应项。确认现有工作已保存后执行准备登录。工作人员完成首次 Windows 欢迎和设置，等管理端显示桌面准备成功。
3. 执行桌面准备、工作目录检查。核对工具配置里的 `powershell` 指向包内 7.6.9 运行时，文件版本为 `7.6.9.500`。在桌面与脚本维护配置导入本包 `contest-scripts-v1.json`，启用 compilecpp、submit，填写编译器工具 ID、DOMjudge 地址、本场比赛 ID 和语言 ID，发布后执行脚本部署。
4. 使用本场配置的 DOMjudge 地址。管理凭据由管理人员从既有受控材料取得。在 DOMjudge 创建正式比赛、题目和参赛组后，在 WCCS 的 DOMjudge 账户页面核对本场名单与 IP，再执行同步。换机后重复核对与同步，以撤销旧绑定和旧网页会话。
5. 在普通账户的比赛终端编译一个小程序，再向测试题提交，核对真实判题结果。已验证的 demo 比赛和合成名单供测试，正式比赛需另行配置。

注意版本：下列手填评测比赛的做法适用于已部署的 schema 19。升级到 schema 20 后，先在 DOMjudge 账号页按名称和编号确认一次绑定，再进行同步和比赛联动；恢复必须覆盖未结暂停座位。升级检查和换机入口见[管理员操作走查](admin-workflows.md)。

## 文件和比赛操作

- 文件分发页面上传资料，选择目标、发布时间和速度，预览后执行。文件在全部校验通过及服务器明确发布后出现在比赛工作目录的 `WCCS-resources` 下。失败原因和补发入口在逐机结果中，已有不同内容的文件会报冲突。
- 比赛安排页面选择 WCCS 比赛、DOMjudge 比赛和座位，预览后执行开始、暂停、恢复或结束，可安排未来七天内操作。目前同时只保留一个活动安排。
- 暂停先关闭 DOMjudge 提交并冻结比赛时间，再让所选桌面等待。恢复先核对所选桌面均已解除，再恢复评测。逐机失败时按显示原因处理并重新预览。暂停成功后桌面部分失败，评测保持暂停，工作人员需要明确恢复。
- 普通等待有效期为 30～3600 秒。比赛暂停需要支持暂停续租的新版客户端，原连接在线时持续到工作人员明确恢复。断线会解除桌面控制，恢复网络后需重新预览并执行。

## 赛后恢复

1. 在赛后恢复页面填写确切目录，先执行检查。目标机只有 C 盘时选择已配置的比赛工作目录。页面会显示卷身份和文件清单。整卷模式仅支持部署设备的固定非系统 D 盘，保留回收站和 System Volume Information。
2. 选择需要归档的源文件后缀，执行归档，下载 ZIP 并打开核对。若本场确实无需收集，填写跳过原因。归档只收集选定后缀，随后清理会删除检查范围内的所有文件及空目录，应在预览中核对完整清单。
3. 从比赛账户页面恢复教学，等策略恢复成功。保存当前会话文件后，回到恢复页面预览并确认清理。文件清单发生变化时会拒绝清理，需要重新检查和归档。
4. 清理完成后可预览并确认重启。页面先显示请求已受理，新宿主上线后核对教学状态并记录首次匹配的时间。如果复原软件同时回滚了任务标记，页面会继续显示待核对，需要现场确认。再次检查工作目录，确认复原软件实际恢复了哪些内容。

使用 schema 19 服务端和对应客户端进行整卷归档前，在每台设备的受保护身份目录准备部署卷配置。例如身份文件为 `device.json` 时，文件名为 `device.recovery-volume.json`。先执行只读检查，工作人员在该机核对 D 盘的设备 ID、卷 GUID 和序列号，按下例填入实际值。配置随设备管理，更换卷或复原镜像后重新核对。缺少配置的设备仍可检查或使用已配置的工作目录。

```json
{"device_id":"现场设备 ID","drive":"D:\\","guid":"检查结果中的完整卷 GUID","serial":"检查结果中的序列号"}
```

部署本轮服务端、Web 和 Nginx 配置后，新客户端使用 recovery-v2，页面可配置最多 100000 个文件和目录，清理总字节数不限。选定源文件归档最多 512 MiB，执行时限默认 60 分钟，最多 24 小时。旧任务保留原 4096 项、总内容 512 MiB 语义。超出本次配置时拒绝操作，保留现场文件。

## 失败时怎么做

- 服务器关闭或断网时，客户端撤销本轮限制并保留当前会话和文件。服务器重开后，工作人员重新批准接入或下发比赛控制。
- 策略恢复失败时查看具体原因，使用该机对应的教学恢复入口（母机专用包为 `04-recover-teaching.cmd`），随后导出诊断。软件关机权限控制作用于本机普通用户权限持有者，保留 SYSTEM 和 Administrators，恢复时按记录还原原持有者。Windows 在下一次登录时更新会话中的这项权限。断网恢复保留当前程序和文件。运行新版本桌面准备后，旧比赛会话可使用 WCCS 目录下“恢复后关机”和“恢复后重启”，点击后确认操作。本机服务须运行且完成教学恢复，服务器可离线。Windows 原生电源菜单在下次登录刷新，原生入口需按现场矩阵核对。
- 诊断包中的 `quarantined_maintenance_count` 给出本机损坏或被服务端永久拒绝的维护回执数。隔离记录留在身份文件旁的维护日志目录下的 `quarantine` 子目录，按任务号核对服务端事件与本机状态。
- 归档失败时保留源文件，修复连接后重新检查和归档。清理中断时可能已有部分文件删除，服务器归档仍在。先下载核对，需要恢复的内容解压到单独目录，再决定如何放回。
- C 盘整盘复原会把本轮身份材料、账户状态和配置还原到镜像版本。机器名用于关联原设备，启动后重新生成随机凭据，管理员批准本轮接入。母机准备好的账户配置文件通过整盘镜像保留，分发后统一下发的新配置在联网后重新获得。
- 在事件记录中打开失败或硬件变化事件，填写处置说明并标记已确认或已解决。硬件变化提示需工作人员核对现场。

USB 策略、关机权限、普通账户工具访问、真实重启和 C 盘复原尚待选定代表机后验证。复原镜像保存需工作人员使用现场复原软件完成。
