# 全项目检查（2026-11-18）

检查基线为 `fix/client-deployment-stability` 的 `c19e8c2`，开始时工作区干净。检查覆盖比赛控制、Windows 维护与恢复、脚本入口、镜像审核、HTTPS 分发、Web 页面和回归入口。以下优先级按误删、比赛公平性、可恢复性和 200～300 台部署影响排列。除标为实测的项目外，结论来自当前源码。容量影响尚未在全场归档负载下测量。

## 建议在批量部署前处理

| 编号 | 问题、触发条件与影响 | 修正与验收 |
| --- | --- | --- |
| 1 | **恢复页面可以推进另一场比赛的清理。** 接口返回授权机房最近 500 条恢复任务，页面全部展示，行标题省略比赛。点击“为本批成功设备准备下一步”会从历史行复制比赛、目标和整批设备。当前选择 B 场时，可以继续 A 场的归档、清理或重启。后端会核对 A 场的清单，仍需要工作人员确认，因此后端清单保护无法发现选错比赛。见 [恢复页面](../../web/src/Recovery.tsx) 和 [恢复查询](../../crates/wccs-server/src/recovery.rs)。 | 服务端按当前比赛查询，页面在继续步骤时校验比赛 ID，确认区域展示比赛名、机房和设备数。用两个有成功归档记录的比赛切换验证。 |
| 2 | **整卷清理可以超出已授权的目标 D 盘。** 协议接受任一盘符，原生客户端验证固定非系统卷、程序路径和本轮卷身份。另一块固定数据盘也能通过；从检查到清理始终指向同一块误选卷时，复核会通过。当前现场说明允许任意明确指定的非系统卷，范围大于需求中的部署目标。见 [需求 REQ-12](../requirements.md)、[协议](../../crates/wccs-protocol/src/recovery.rs) 和 [原生卷核对](../../crates/wccs-agent/src/recovery.rs)。 | 把可整卷清理的部署卷作为独立受控配置，按盘符及已核对卷身份匹配。用合成卷信息覆盖授权 D 盘、另一数据卷、盘符复用和只有 C 盘的设备。 |
| 3 | **网络正常时，长时间暂停也会自行释放选手桌面。** DOMjudge 的暂停持续到明确恢复，但桌面沿用等待命令，默认 900 秒、最多 3600 秒，到期后服务端停止下发，客户端退出等待并恢复账户。现场手册已提示值守续期，这仍使一次暂停操作无法持续保证两端一致。见 [联动实现](../../crates/wccs-server/src/contest_control.rs)、[等待期限](../../crates/wccs-server/src/waiting.rs)、[客户端空命令处理](../../crates/wccs-agent/src/host.rs) 和 [现场说明](m3-m5-field-guide.md)。 | 在原有连接、身份和管理授权持续有效时，按暂停状态维持短租约。覆盖在线超过期限、真实断线与重连三个分支，保留断线立即退出、重连须重新授权的要求。 |
| 4 | **解绑座位后，WCCS 缺少撤销旧 DOMjudge IP 的入口。** 名单页允许清空座位，提交会删除分配。同步器将无座位选手标为不可执行，旧账号及 IP 仍可保持启用。把该座位交给新人时，旧账号又会使新同步报 IP 冲突。正常的两名已分配选手互换已有专门流程，缺口发生在先解绑或退赛。见 [名单提交](../../crates/wccs-server/src/roster.rs) 和 [评测账号同步](../../crates/wccs-server/src/domjudge.rs)。 | 支持只撤销旧绑定及会话的任务，并保留回执。验收已同步选手解绑、原座位重用与撤销失败后的重试。 |
| 5 | **发布资料时可能覆盖刚出现的同名文件。** 客户端先确认目标不存在，再组装、同步和校验临时文件，最后调用 `fs::rename`。本机固定 Rust 1.99.1 的 Windows 标准库实现使用 `MOVEFILE_REPLACE_EXISTING`。在两次操作之间生成的同名文件会被替换。既有测试只覆盖发布前已经存在的文件。见 [发布与测试](../../crates/wccs-agent/src/distribution.rs)。 | 使用目标已存在即失败的原子发布操作。以临时目录验证发布前出现的同名文件内容保持完整。 |
| 6 | **大归档核验会占用控制心跳的唯一写连接。** `finish` 在全程持有 `app.db` 时逐文件查询所有分块，并计算分块与整文件摘要。许多小文件会产生大量查询，大文件会增加读取和计算时间。同期 WSS 心跳排队，原生维护 HTTP 请求的总超时只有 3 秒，可能出现归档已在服务器完成但客户端记为失败，或其他机器因续租延迟退出控制。见 [归档核验](../../crates/wccs-server/src/recovery.rs)、[数据库连接](../../crates/wccs-server/src/database.rs)、[控制心跳](../../crates/wccs-server/src/control.rs) 和 [客户端超时](../../crates/wccs-agent/src/maintenance.rs)。 | 分块校验在受限的独立工作连接上执行，完成时短事务复核任务状态与授权，客户端可查询终态。联合测量多小文件、接近 512 MiB 的归档和 300 台持续心跳。 |
| 7 | **取消分发与本地发布可能给出相反结果。** 设备按最后一次轮询的 `publish` 决定写文件。组装期间取消任务，设备仍可完成发布。服务端对已取消任务接收回执但保留“已取消”，客户端只检查回执中的任务号与 `accepted`。页面可能显示已取消，而资料已经可见。见 [客户端发布](../../crates/wccs-agent/src/distribution.rs) 和 [取消与进度](../../crates/wccs-server/src/distribution.rs)。 | 增加服务端原子领取的发布阶段，清楚区分可取消、已开始发布和最终实际结果。验收取消与发布交错的两种顺序。 |

| 10 | **恢复列表每两秒传输完整文件清单。** 查询最多取 500 条含命令和结果的历史记录，再返回包含完整清单的结果。页面即使折叠详情仍为每个文件构造列表项。单设备允许 10 万项，多机操作后读取、传输和渲染都会随历史清单增长。见 [列表查询](../../crates/wccs-server/src/recovery.rs) 和 [页面轮询与清单](../../web/src/Recovery.tsx)。 | 列表只返回计数、大小、状态与版本，详情按任务分页读取。按真实文件数量测量响应体与页面首次可操作时间。 |
| 11 | **客户端维护日志会在空闲时反复全量读取，累计 4096 条后拒绝新任务。** 每轮轮询都读取、反序列化两个目录的全部记录，已确认记录也保存完整命令和结果，大清单会在历史中反复被读取。达到上限后，新命令在接收回执之前返回错误。见 [维护循环与容量检查](../../crates/wccs-agent/src/maintenance.rs)。 | 分开索引待发送记录与已确认记录，将后者压缩为去重所需字段。验证超过 4096 个历史任务后仍能领取新任务且旧任务不会重复执行。 |
| 12 | **一条无法补报的旧维护回执可以阻断之后所有任务。** 每轮先逐条补报，发送失败立即返回，尚未进入新任务轮询。例如客户端保留未确认回执而服务端从较早备份恢复、已无该任务时，会反复收到拒绝。历史 JSON 损坏还会使启动恢复直接退出维护线程。见 [补报与启动恢复](../../crates/wccs-agent/src/maintenance.rs) 和 [服务端结果归属核验](../../crates/wccs-server/src/maintenance.rs)。 | 区分瞬时错误、永久拒绝与仍涉及本机副作用的未决记录。隔离并展示异常记录，验证独立任务可继续，旧副作用不会重放。 |
| 13 | **“已观察到重启”会随健康数据变旧而消失，也可能归到错误任务。** 接口按当前实例、当前在线状态、uptime 与任务创建时间即时推断，未保存首次观察，也未要求该重启任务成功。后续普通断网会把原先确认的观察改回未知，稍后一次无关重启也可能让先前失败的任务显示已观察。见 [观察条件](../../crates/wccs-server/src/recovery.rs) 和 [页面呈现](../../web/src/Recovery.tsx)。 | 记录重启请求受理时间、请求前启动标识和首次匹配的教学状态，持久保存观察时间。验收失败任务、后续人工重启及确认后再次离线。 |
| 14 | **全场比赛联动会反复逐座查询在线状态。** 每次执行桌面计划都会对每个席位单独发一次 SQL。等回执时每轮先休眠 250 毫秒，再占用心跳共用连接重算这份计划。300 席即每轮额外 300 次顺序查询。现有容量测试走普通等待命令。见 [比赛联动](../../crates/wccs-server/src/contest_control.rs) 和 [容量测试](../../crates/wccs-server/tests/cases/capacity.rs)。 | 批量读取连接状态，复用等待计划已有的批量控制记录。按 300 席暂停、恢复各测一次，记录心跳、回执延迟和超时数。 |
| 15 | **归档扩展名难以逐个键入。** 受控输入框每次键入都按空白拆分、丢弃空项，再用单空格回显。末尾刚输入的分隔空格立即消失，再输入下一个扩展名会拼到前一个，例如 `cpp` 和 `h` 变成 `cpph`，两类源文件都可能漏收。粘贴完整列表可以绕开此行为。见 [扩展名输入框](../../web/src/Recovery.tsx)。 | 保存原始编辑字符串，在预览时再标准化，并显示实际归档文件数与清单。验证逐键输入、粘贴和只添加一个后缀。 |
| 16 | **合法的长中文文件名可阻断整棵目录的恢复检查。** 扫描复用了分发文件名规则，每段最多 180 个 UTF-8 字节。例如 60 个常用汉字加 `.cpp` 已有 184 个字节。只要目录中存在这类文件，检查就以通用错误结束，操作员看不到具体文件。见 [扫描](../../crates/wccs-agent/src/recovery.rs)、[路径验证](../../crates/wccs-protocol/src/recovery.rs) 和 [文件名限制](../../crates/wccs-protocol/src/distribution.rs)。 | 区分资料命名约束与已有 Windows 文件的清单表示，保留路径安全校验。用合法长中文名和必须拒绝的路径分别覆盖检查与归档。 |
