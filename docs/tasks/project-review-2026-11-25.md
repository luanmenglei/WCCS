## P1　部署前处理

| 问题 | 证据、影响与修复验收 |

| 1. 控制断线后，旧维护任务仍可被领取 | 首次 WSS 交换撤销等待指令，维护任务只记录宿主实例和 Windows 会话。维护轮询、续权和归档校验检查当前连接在线，却没有比较创建任务时的连接。服务端重启也只把控制设备标离线。设备以同一宿主和会话重连时，尚未领取且未到期的清理、重启等任务仍可下发；本机卷、归档及教学状态检查通过后即可执行。将维护任务绑定到提交时的连接与服务端实例，退役旧执行授权，同时保留已执行结果的补报。用合成设备验证同一宿主断线重连、控制器重启和旧回执补报三个分支。[控制连接](../../crates/wccs-server/src/control.rs) · [维护授权](../../crates/wccs-server/src/maintenance.rs) · [归档授权](../../crates/wccs-server/src/recovery.rs) |
| 2. Windows 正式服务的资料分发线程在第一次轮询前失败 | 宿主将身份文件路径规范化，再把它传给分发线程。线程以该路径派生缓存目录，要求第二个字符是盘符冒号。**本机实测**使用仓库固定 Rust 和实际协议库，同一目录的普通盘符形式通过，Windows 规范化返回的扩展长度路径被拒。错误发生在联系分发接口前，即使控制心跳正常，该设备也可能一直显示分发离线。区分本机已解析路径与网络下发路径的校验，保留重解析点防护。验收应从宿主入口启动测试模式，观察登记、下载和发布三个结果。[宿主](../../crates/wccs-agent/src/host.rs) · [分发](../../crates/wccs-agent/src/distribution.rs) · [目录检查](../../crates/wccs-agent/src/file_transaction.rs) |

| 4. 大维护回执在设备认证之前占用服务资源 | 代理和应用允许单个回执达到 128 MiB。处理函数先经 Axum 的 JSON 提取器读取、解析内容，又先调用结果校验，之后才查设备凭据。只要可达该内网服务，无效身份的请求也可能消耗代理临时存储、应用内存和 CPU；控制心跳与其共用进程。把设备鉴权前移到读取大请求体之前，限制并发接收和解析预算。用仪表化回归确认无凭据请求在解析前结束，并测量多台合法设备交回大清单时的内存和心跳。[路由](../../crates/wccs-server/src/routes.rs) · [回执入口](../../crates/wccs-server/src/maintenance.rs) · [代理](../../config/linux/nginx.conf.in) |

## P2　故障恢复、数据一致性与运维

| 问题 | 影响与修复验收 |
| --- | --- |
| 5. 取消定时开赛后，评测端仍可能处于禁止开赛和提交的状态 | 未来开赛任务会提前执行 `hold_start`，关闭 DOMjudge 的自动开始和提交。取消只更新 WCCS 任务，页面提示“比赛安排已取消”。如果原评测安排应继续生效，就会错过原定开赛时间。保留预置前状态，取消时展示实况并提供受远端版本保护的明确恢复操作。分别验收预置前取消、预置后取消以及评测端已被裁判修改。[调度与取消](../../crates/wccs-server/src/contest_control.rs) · [评测扩展](../../integrations/domjudge/WccsControlController.php) · [页面](../../web/src/ContestControl.tsx) |
| 6. 未领取的维护任务取消后继续占用设备 | 取消只置 `cancel_requested`，领取查询随即排除该任务，设备无法为未见过的任务回报终态。维护和等待的忙碌判断继续把该行计入，直到过期。恢复任务最长可占用 24 小时。将已确认未开始的任务转为终态，对已开始的任务保留停止确认；核对取消后新维护可预览、实际执行中的清理不会与新任务重叠。[取消与忙碌判断](../../crates/wccs-server/src/maintenance.rs) · [等待计划](../../crates/wccs-server/src/waiting.rs) |
| 7. 一条损坏或永久被拒的分发回执会堵住后续资料 | 分发线程先遍历回执文件，读取、解析和上报任一步出错就退出本轮。下次轮询仍先处理同一条记录。数据库恢复导致某个旧任务号不存在时也会触发。一条记录可阻断无关的新任务。复用维护模块已有的隔离及诊断处理，区分可重试网络失败和永久拒绝，并验证新任务继续被领取。[分发回执](../../crates/wccs-agent/src/distribution.rs) · [已有隔离实现](../../crates/wccs-agent/src/maintenance.rs) |
| 8. 回执历史已分页，批量恢复的预览与提交仍携带每台设备的完整清单 | 从检查进入归档、清理或重启时，服务端逐机读取完整文件与分块摘要，将清单合并到预览；提交时在共用业务连接上重建计划、计算摘要并持久化和返回整批回执。浏览器也先解析完整 JSON 再显示清单。多机、大目录的批准操作可能超时，并拖慢心跳。使用不可变清单引用、摘要和逐机汇总确认，详情按需分页。容量回归应对完整批次执行真实预览和提交，测量返回字节、峰值内存及心跳延迟。[恢复计划](../../crates/wccs-server/src/recovery.rs) · [批量提交](../../crates/wccs-server/src/maintenance.rs) · [页面](../../web/src/Recovery.tsx) |
| 9. 现场查看事件也会下载整份恢复清单 | 维护结果直接把含文件清单的回执写入事件详情，通用事件列表在持有主业务数据库连接时读取并返回每一行的全部详情，默认一页 50 条。历史恢复页面的分页没有覆盖此入口。将事件列表投影为摘要，大清单通过已有分页接口查看；在保留 50 条大回执的情况下验证事件首屏体积和并发心跳。[维护事件写入](../../crates/wccs-server/src/maintenance.rs) · [事件查询](../../crates/wccs-server/src/events.rs) |
| 10. 下载大归档时先在内存生成完整 ZIP，并占用管理预览连接 | ZIP 使用内存缓冲区，按文件逐次查全部分块。大量小文件会产生大量串行查询，直到整个 ZIP 完成才返回响应头。若超过全局 15 秒请求期限，下载无法开始；同时其他管理预览排队。用独立工作连接顺序读取分块，流式输出或预生成可下载文件。分别覆盖单大文件和大量小文件，测首字节时间及同时进行管理预览的延迟。[归档下载](../../crates/wccs-server/src/recovery.rs) · [请求期限](../../crates/wccs-server/src/routes.rs) |
| 11. 设备凭据的短暂文件锁争用，可能让整个 Windows 服务以成功状态退出 | 多个工作线程启动后各自读取凭据。凭据函数用不共享的文件锁，没有等待或重试；若首次启动 HTTP 线程恰好未拿到锁，它会设置全局停止标志。其他线程正常收尾时宿主返回成功，SCM 可能将其记为正常停止。启动工作线程前初始化凭据，对暂时的共享冲突有界重试，向 SCM 准确报告初始化失败。验收同时启动各工作线程以及真实不可读配置两个分支。[凭据锁](../../crates/wccs-agent/src/diagnostics.rs) · [启动错误](../../crates/wccs-agent/src/windows_agent.rs) · [SCM](../../crates/wccs-agent/src/service.rs) |
| 12. 全场登录共用一个限流桶，正常的镜像批量启动也会触发注册限流 | 登录请求在查账号前进入同一配额，其他来源的失败请求可以导致值班管理员被限流。镜像申请也共用单桶；待审核服务约每 5 秒重试，300 台同步待审核的理论请求量约 3600 次/分钟，高于 600 次/分钟的配额。区分来源、账号与总预算，对已登记申请退避并加随机抖动。验证一处登录异常时其他管理员仍可登录，并测量批量开机首轮登记所需时间。[限流](../../crates/wccs-server/src/auth.rs) · [镜像注册](../../crates/wccs-server/src/image.rs) · [服务重试](../../crates/wccs-agent/src/windows_agent.rs) |
| 13. 新标签打开带比赛参数的链接会丢失比赛选择 | **Edge 实测**使用本次生产构建及回环合成 API。直接打开指向比赛 alpha 的名单页，比赛选择为空；在同一页跳转到 beta 时能正确选中。页面只在后续 `hashchange` 读取比赛参数，登录成功也重置比赛。初始化和登录恢复时从当前地址解析，再按已授权的比赛快照校验。覆盖书签、新标签、刷新和重新登录。[页面入口](../../web/src/App.tsx) |
| 14. 配置 HTTPS 入口时可以意外把明文后端暴露给赛场网络 | `origin` 是 HTTPS 时，配置校验接受非回环 `bind`，而 Rust 进程的监听器只提供 HTTP。若管理员换机时绑定到所有网卡，且主机防火墙允许访问该端口，设备 API 和登录接口会出现绕过 Nginx 的明文入口。仓库部署模板的回环配置可避免这个条件。对本机代理拓扑校验回环绑定，需要跨主机代理时显式配置受保护的上游通道。验收应检查实际监听接口和直连可达性。[配置验证](../../crates/wccs-server/src/app.rs) · [监听器](../../crates/wccs-server/src/main.rs) · [部署模板](../../config/linux/nginx.conf.in) |
| 15. 已存在的脚本目录可能通过只读检查，但选手仍能改写已有文件 | 新目录会设置 ACL；复用现有目录时只尝试以比赛账户打开根目录并申请 `FILE_ADD_FILE`。此权限不足以证明已有启动器、脚本或激活配置不可修改，也没有区分拒绝访问与其他打开错误。如果部署时保留了可写子文件的 ACL，普通比赛账户仍可改动共享命令，影响编译或提交结果的可信度。核对受信文件及其父目录的实际写入、替换和 ACL 修改权限。用“根目录不可新建、已有文件可改写”的权限模型做隔离验收。[脚本部署](../../crates/wccs-agent/src/preparation.rs) · [启动器](../../scripts/contest-launch.ps1) |
