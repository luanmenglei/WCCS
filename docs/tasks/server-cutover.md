# 服务器切换操作说明

适用于计划换机、服务器故障接管，以及从旧 IP 部署迁移。控制器、数据库、入口和客户端的责任见 [ADR 0017](../decisions/0017-site-deployment-and-cutover.md)。

## 赛前准备

1. 记录当前 HTTPS origin、证书 SAN 与 CA、解析或 IP 归属、Nginx 可信代理、服务版本及数据库 schema。已有 IP 客户端若要原样接入，候选机接管相同 IP 并提供对此 IP 有效的证书。首次改用内网名称需安排一次新入口部署。
2. 按 [Linux 部署记录](linux-deployment.md)在候选机准备服务账户、服务端与对应 Web 资源、配置及证书。候选机的服务保持停止，避免开机自启接管。核对系统时钟与部署账号读取权限。镜像使用公开 CA，CA 私钥留在签发端。
3. 在独立库演练备份恢复，核对最近比赛、待恢复的暂停座位、请求号及归档。核对 DOMjudge 的库、连接材料与实际比赛。记录备份时间和此后新写入的处理方式。
4. 在候选机以服务账户、从与 systemd 一致的工作目录执行只读检查。该命令只读取配置、静态入口与数据库状态，既不监听端口也不启动业务任务。

```sh
cd /opt/wccs/current
sudo -u wccs ./wccs-server --check-standby /etc/wccs/server.json
```

核对输出中的 `origin`、`database_schema`、`target_schema`、`migration_required` 与 `database_read_only`。只读副本可完成检查；正式接管前需要可写数据库。空库首次安装走初始化流程。需要迁移时先在恢复副本完整演练，预检成功只说明版本落在支持范围。

## 接管同一赛场

1. 管理员停止安排新操作，核对正在执行的比赛联动、维护、分发和归档。比赛进行中由裁判决定暂停，另行核对 DOMjudge 计时与提交状态。计划切换先释放桌面，确认教学恢复。故障时逐机状态可能未知，留待重连核对。
2. 停止并禁止旧控制器自动启动。旧主机失联时，先通过电源、虚拟化或网络管理确认隔离，并核对旧调度器无法再访问 DOMjudge。共享同一个库的新版实例还有数据库锁保护；各自持有数据库副本的两台机器必须在基础设施层隔离。
3. 有数据库迁移时，冻结旧库写入，完成最终同步或恢复，再核对最后写入点。候选机使用最终配置复跑预检，确认库可写。成套启动新版服务与 Nginx，启用新主机的服务自启。退出码 78 表示库中还有活动控制器，应回查持有者。
4. 使用管理机已经信任的 CA 检查候选入口的 HTTPS 和代理。下例针对稳定内网名称，`SITE_NAME`、`CANDIDATE_IP` 和 `CA_FILE` 由部署方填写。

```sh
curl --noproxy '*' --fail --cacert "$CA_FILE" \
  --resolve "$SITE_NAME:443:$CANDIDATE_IP" "https://$SITE_NAME/api/ready"
```

5. 将稳定名称或服务 IP 指向候选机。在实际管理机打开原书签，重新登录，在“服务入口诊断”检查两项结果。先核对一个机房的一台代表机，查看新心跳、控制连接、实际桌面、座位与凭据代次，再核对其余设备。重新预览并确认本场需要的控制；旧请求按原编号检查。

## 更换信任域与回退

目标是独立新入口时，先从旧系统恢复教学，撤销旧设备凭据。准备含新 origin 和 CA 的干净母机镜像或用既有单机安装流程部署独立逐机材料，在新系统开启注册窗口、核对机器名和来源 IP、审批后再试一台。镜像调整及教学恢复见[母机操作手册](image-deployment-field-guide.md)。保留选手会话和文件的要求决定重新封装或安装应安排在赛间维护窗口。

新主机尚未接受业务写入时，隔离候选机，核对旧库及程序兼容性，再恢复原入口和原主机。新主机已有写入时，以最新库为准，先对账再回切；如旧程序不兼容新 schema，使用兼容程序接管最新库。回退成功以代表机回执、后台任务和 DOMjudge 状态共同确认。
