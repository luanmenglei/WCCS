# WCCS 管理界面规范

2026-11-10 用户要求界面与核心赛场管理能力对齐 Natsume，并明确排除打印和拍照。

参考固定为 Natsume `v2` 的 `9b2dca59cf2cd4358c02bc051e318da44cda85e4`，包含 DESIGN.md、页面实现及仓库图库。上游仓库声明 AGPL-3.0-or-later。当前界面使用 WCCS 既有 React 组件和 CSS 实现，依赖及字体沿用当前锁文件。[上游设计规范](https://github.com/4o3F/Natsume/blob/9b2dca59cf2cd4358c02bc051e318da44cda85e4/DESIGN.md)

## 视觉与布局

- 主表面白色 `#ffffff`，次级表面 `#f4f4f4`，边框 `#e0e0e0`。
- 主文字 `#161616`，次级文字 `#525252`，主操作与焦点使用蓝色 `#0f62fe`。
- 成功、待处理和冲突通过绿色、黄色、红色配合文字表示。
- 控件和容器使用直角、1px 边框，间距使用 4、8、12、16、24、32px。
- 页面标题 32px、400 字重，普通后台正文 14px。字体使用随资源打包的 Geist，中文回退 Microsoft YaHei，标识符和路径使用 Consolas。
- 左侧分组导航承载页面入口，顶部面包屑标明当前位置。选中页面带蓝色左边线，只有当前业务页对用户可见。
- 座位页采用覆盖率统计、筛选条和紧凑座位图，支持列表视图。网格保持实际行列位置，筛选后的空位保留位置占位。
- 设备页使用表格和详情侧栏。详情以原生 dialog 提供焦点管理、Escape 关闭与模态语义。
- 窄屏采用可展开导航、两列统计及容器内部横向滚动，交互控件至少 48px 高。

## 页面与交互

当前入口为座位、设备、选手名单、注册审核、检查任务、机房设置、工具配置、操作员和全局事件。功能差距及后续页面见 [对齐记录](tasks/natsume-alignment.md)。

机房与工具草稿在本次登录内跨页保留，显式重新加载读取服务端最新版本。退出或会话失效会清除当前登录的临时状态。旧会话响应通过会话代次隔离，重叠刷新仅接受最新发起请求的结果。

座位与检查任务页面共享目标选择。筛选结果可批量选择，实际执行前展开设备及跳过原因。配置版本或选择变化使旧预览失效，服务器在提交时再次校验实际关联和状态。

状态始终来自认证 API。页面显示最近刷新时间、离线、结果过期、部分失败及未配置，操作结果按已有后端权限和事务语义处理。

设备生命周期筛选和详情沿用表格与侧栏。注册审核页展示窗口截止时间、申请状态与人工核对入口。每次逐设备操作显示设备 ID、基准版本和实际影响，失败保留同一请求重试，版本冲突提供取消和刷新路径。凭据材料只在签发操作后临时显示，历史列表按事件与任务分别分页。

名单页沿用 Preparation 的导入、差异核对和提交流程。全局显式比赛选择用于名单、座位和设备详情，刷新或新登录后重新选择。导入预览列出行号、前后资料和座位影响，自动分配显示顺序、机房范围及跳过项。编辑侧栏锁定打开时版本，提交保留请求编号供重试，状态改变后可重新预览。历史按比赛和游标读取，详情保留当时资料与位置。

## 操作员与全局事件

系统管理导航提供操作员和事件页面。侧栏展示显示名、账号、角色、权限版本和机房范围。账号编辑侧栏先显示目标、当前权限和变更影响，再确认提交，持久请求编号可直接关联事件。初始密码和重置材料只在编辑流程暂存，历史及普通响应脱敏。

事件提供时间、人员、类型、来源、设备、机房、比赛、请求和结果筛选，表格、详情侧栏与原业务链接复用现有布局。游标翻页保留查询水位，重新查询刷新最新事件。未知历史身份、时间和范围分别标注，设备回报与管理动作分别展示。

只读身份保留查看操作，写入控件按角色禁用或隐藏，全局写入要求在页面说明。401 统一撤销本会话全部异步请求、草稿和预览；Cookie 被其他标签页切换时通过会话绑定识别。授权规则见 [ADR 0009](decisions/0009-operator-events.md)。

## 等待控制

`#/waiting` 复用全局比赛选择、座位筛选和跨页选择。操作区明确进入或结束等待及有效期，预览固定选手、设备代次、机房与会话，列出逐项跳过原因。提交反馈保留请求编号，失败可重试原预览。

逐机表独立显示期望、命令阶段和当前实际状态，历史完成后发生窗口退出仍显示实际失败。重新核对只刷新状态，异常目标重试需重新预览。详情关联全局事件。只读身份保留查询，权限失效沿用全局登录清理，断线暂停写入。实现和截图见 [等待控制记录](tasks/m2-waiting-control.md)。

## 比赛账户入口

`#/login` 与等待控制共用比赛、座位和固定预览。展示账户所有权及 SID、会话类别、工具权限、离线恢复入口、教学账户状态和跳过原因。准备登录前显示执行步骤、工具配置版本与完整路径；教学会话注销使用独立的“工作已保存”确认。列表区分已接收、执行中、桌面确认、失败、恢复中和恢复失败，并显式标记模拟或 Windows 测试证据。断线时实际状态显示未知。登录完成后链接等待控制，恢复操作关联全局事件。

## 选手等待界面

2026-11-12 按用户最新要求采用 xcpc-tools 的 `PresentationPage` 布局。背景 `#050505`、卡片 `#080808`、主文字 `#f5f5f5`、辅助文字 `#a3a3a3`，采用白色缓慢漂移粒子、居中学校缺省图标和圆角身份卡片。左上角显示比赛名称，右上角显示当前时间，卡片左列为座位、右列为姓名和学校，底部显示 WCCS 与等待提示。[固定视觉参照](https://github.com/hydro-dev/xcpc-tools/blob/cfb5cc8a7c4df82c29be6354adf2997b5f9258c6/packages/machine-tools/frontend/src/components/PresentationPage.tsx)

字体使用系统 Microsoft YaHei UI，时钟使用 Consolas。布局依据客户区宽高重新计算，覆盖横屏、竖屏及小尺寸窗口，PMv2 下使用实际像素。长文本先按 GDI 实测缩小，最小字号为 12～16 物理像素，超过宽度使用省略号。原生静态控件保留完整可访问身份，学校与比赛名称中的 `&` 按字面显示。校徽配置与比赛起始时间尚待 M3 数据接入，当前时间只用于展示。授权期限继续使用单调时钟。

键鼠触碰后显示覆盖层，包含上游 `szm_no.png` 转换的内嵌 BMP、“DON'T TOUCH MOUSE AND KEYBOARD”和“请勿触碰鼠标和键盘”。连续触碰刷新三秒截止时间，停手三秒后恢复身份卡片。动画以 20 FPS 为上限，尊重 Windows 客户区动画偏好，提示显示期间暂停背景重绘。原生双缓冲与子窗口裁剪避免闪烁和覆盖交叠。独立开发预览及受控 test 模式展示开发标记、聚合计数和退出按钮。素材来源、许可与转换记录见 [素材说明](../crates/wccs-session/assets/README.md)，实际验证与剩余环境条件见 [审查记录](tasks/xcpc-waiting-review.md)。
