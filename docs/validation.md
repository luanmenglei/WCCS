# 验证方案

## 当前可执行检查

```powershell
python scripts/check_repo.py
python scripts/check_repo.py --staged
python -m unittest discover -s scripts/tests -v
git diff --check
git diff --cached --check
```

仓库检查使用标准库，检查 Git 可见文件的文本编码、换行、行末空白、单文件大小、常见敏感文件名和 Markdown 相对文件链接。默认检查工作区及未忽略的新文件，`--staged` 检查暂存快照。外部网页和 Markdown 标题锚点由人工核对。

## 后续自动化验证

首个应用切片需要同时提供构建和运行入口。协议状态逻辑、身份迁移、重试、删除范围和不确定提交结果需有回归验证。集成验证使用临时数据、合成选手与隔离的 DOMjudge 测试实例。

容量验证由模拟客户端执行，模拟器应覆盖协议、认证和事件行为。Windows 会话及复原能力另外通过真实系统验证。

## 容量验收目标

下表为初始验收目标，运行时记录服务器配置、数据库版本、网络、客户端版本、采样窗口和原始结果。根据机房实测调整时更新 ADR 与本表。

| 场景 | 初始验收目标 |
| --- | --- |
| 500 个模拟客户端持续 60 分钟 | 任务状态一致，队列有界，内存无持续无界增长，已连接客户端心跳得到处理 |
| 300 个客户端集中上线 | 采用退避，在服务器可达后 60 秒内完成注册和当前状态同步 |
| 300 台在线机器普通控制命令 | 排除网络故障，接收确认 p95 ≤ 2 秒；执行时间按具体操作记录 |
| 提前下发统一开始安排 | 时钟偏差满足条件时，界面开放时间差目标 ≤ 1 秒 |
| 文件满速分发期间控制任务 | 维持上述接收确认目标，分别记录吞吐与控制延迟 |
| 服务端重启或短时断网 | 已持久任务可恢复，过期命令被拒绝，重连后无重复副作用 |
| 多管理员同时更新绑定 | 冲突可观察，同场选手和座位的有效绑定保持唯一 |

## Windows 与机房演练

| 场景 | 需要的证据 |
| --- | --- |
| 教学时服务器关闭及随后开启 | 普通教学正常；明确启用比赛后才出现等待界面 |
| 多屏、缩放、快捷键、会话切换 | 界面状态与实际操作一致，异常退出能恢复 |
| 自动登录三类场景 | 开机登录、即时登录、已有会话解锁分别记录支持条件及结果 |
| 普通账户和管理员账户 | 客户端权限、IPC 调用限制及系统策略实际效果 |
| USB 插拔和替换键鼠 | 存储与设备限制生效，原有外设可用，授权替换可追踪 |
| 编译与提交 | 中文路径、失败输出、API 超时、重复请求及网页登录 |
| IP 变化和故障换机 | 旧绑定撤销、新绑定生效，旧机恢复后无法接管新绑定 |
| P2P 端口放行和关闭 | 授权互传、损坏块拒绝、节点退出、回源和续传结果 |
| 镜像复原后启动 | 客户端存在且启动，重新注册，系统策略和教学状态符合预期 |
| D 盘清理中断及重启 | 卷与路径正确，归档条件满足，部分失败可恢复，旧任务不会重放 |
| 时钟回拨和比赛延时 | 安排版本一致，异常时间处理及恢复教学行为符合配置 |
| 连续两场比赛 | 姓名、账号、文件、任务和浏览器会话正确归属 |

清理验证先使用临时目录，再使用带快照的测试卷，最后在部署目标上演练。真实 D 盘清理前校验实际卷与比赛目标配置；测试重解析点指向目标外目录时，应证明目标外内容得到保护。

## 结果记录

任务记录或演练报告保存日期、版本、环境、命令、预期、实际结果及失败复现方式。大型日志放在 `artifacts/`，文档记录摘要和获取位置。实测通过、模拟通过及尚待验证分别标注。
