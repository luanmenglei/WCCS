# 验证方案

## 当前可执行检查

```powershell
pwsh -NoProfile -File scripts/check-rust.ps1
python scripts/check_repo.py
python scripts/check_repo.py --staged
python -m unittest discover -s scripts/tests -v
git diff --check
git diff --cached --check
```

仓库检查使用标准库，检查 Git 可见文件的文本编码、换行、行末空白、单文件大小、常见敏感文件名和 Markdown 相对文件链接。默认检查工作区及未忽略的新文件，`--staged` 检查暂存快照。外部网页和 Markdown 标题锚点由人工核对。

`check-rust.ps1` 在 Windows 上固定 Rust 1.99.1、MSVC 14.44.35207 和 SDK 10.0.19041.0，编译运行最小 C / Rust 程序，并执行采集器与等待界面的发布构建、rustfmt、Clippy 和测试。权限不足及缺失字段使用合成数据和可替换查询验证，CLI 集成测试在独立临时目录运行真实 Windows 采集并清理自身产物。工具测试核对未配置时零文件访问、精确路径检查、PATH 中同名文件存在时的缺失结果、目录错误、任意脚本文件名、配置版本回传及旧报告读取。首轮结果见 [M1 任务记录](tasks/m1-inventory.md)，当前结果见 [路线图](roadmap.md)。

## 后续自动化验证

M1 等待界面已纳入同一 `check-rust.ps1`，执行 `wccs-session` 的 release 构建、格式、Clippy 及 9 项测试。开发机真实窗口已核对身份、键鼠计数及冷却提示、重复启动、按钮／Esc／Alt+F4／Tab+Enter 退出和异常终止后的恢复。会话状态及几何布局通过合成测试，实际多屏、混合 DPI 和系统会话条件另行验收。[命令、结果与条件](tasks/m1-session-waiting.md)

采集切片已有构建和运行入口。后续协议状态逻辑、身份迁移、重试、删除范围和不确定提交结果需有回归验证。集成验证使用临时数据、合成选手与隔离的 DOMjudge 测试实例。

容量验证由模拟客户端执行，模拟器应覆盖协议、认证和事件行为。Windows 会话及复原能力另外通过真实系统验证。

## Linux、Rust 与 Web 验证

首个工程落地后固定以下验证矩阵，并把可执行命令加入开发脚本。

| 环境 | 检查范围 |
| --- | --- |
| Windows + Rust MSVC + Windows SDK | 共享模块、客户端服务、原生等待界面、运维采集工具的格式、Clippy、单元测试与构建 |
| Windows + 已固定脚本解释器 | compilecpp / submit 的命令契约、实际编译提交、离线依赖、版本激活与回退 |
| Linux + Rust | 共享模块、Axum 服务、模拟器、数据库迁移及服务启动、停止、恢复 |
| Node.js 构建环境 | React / TypeScript 类型检查、lint、组件测试、生产静态资源构建 |
| 管理员浏览器 + Linux 服务 | 生产资源加载、API/WSS、登录、授权、断线恢复和业务端到端流程 |

Rust FFI 审查覆盖 unsafe 的前置条件、句柄释放、回调存活时间、线程要求和 panic 边界。客户端记录教学待机、等待界面、正常比赛、文件传输时的 CPU、内存、句柄及线程数量，并检查持续运行与重复模式切换后的资源变化。

## 竞赛脚本验收

- 从 cmd、PowerShell 和选定比赛终端调用，核对参数、工作目录、标准输入输出与退出码。
- 覆盖中文、空格和特殊字符路径、编译错误、过期输出、缺失解释器或依赖。
- 使用测试 DOMjudge 核对账号、比赛、题目、语言、确认交互、提交编号及网络异常，验证网页 IP 登录和脚本 API 认证。
- 离线安装并激活脚本包，验证文件摘要、依赖、配置版本、更新中断、运行中更新和回退。
- 自行实现以命令约定验收；复用部分增加上游行为对照及来源、版本和修改记录检查。

下表为初始验收目标，运行时记录服务器配置、数据库版本、网络、客户端版本、采样窗口和原始结果。根据机房实测调整时更新 ADR 与本表。
